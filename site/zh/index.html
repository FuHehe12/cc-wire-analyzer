失败之后，先找共同点。

  1. 从列表定位失败请求，查看错误聚合。
  2. 打开样本，核对响应内容与停止原因。
  3. 确认是上游错误、工具失败，还是记录不完整。

HTTP 成功不一定代表请求没有错误；SSE 内容中也可能携带失败。

查看失败调查步骤

把输入和输出分开读。

  1. 查看 System、Messages、Tools 与调用参数。
  2. 对照响应、工具调用和工具结果。
  3. 需要时翻译或解读片段，再回原文核对。

只有上游返回并被录制的 thinking 才能查看；模型解释不等于已证实的原因。

查看详情阅读方法

沿时间线找关系与等待。

  1. 按会话与泳道定位相关轮次。
  2. 展开工具调用、重试及辅助请求。
  3. 从关系图回到请求，检查派发内容和返回结果。

部分父子关系来自匹配推断，时间相邻也不自动代表因果。

记录在本机，
数据去向说清楚。

本地保存与网络转发是两回事。使用模型分析前，先确认发送范围与端点。

录制
Claude Code 请求经过本机代理，继续发送到已配置的模型上游；软件在本机保存记录。
阅读
查看已保存的请求和确定性统计不需要调用分析模型。记录支持本地压实与归档。
模型分析
翻译、AI 解读和语义分析会把相应内容发往你配置的模型端点。
分享与更新
记录正文可能含消息、文件和敏感信息，分享前需检查。更新检查与下载也会联网。
