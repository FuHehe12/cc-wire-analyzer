## 核心概念（先认术语，后面不再解释）

CC Wire Analyzer 的 UI 围绕几个 CC 内部概念组织，第一次接触会撞墙——这里一次性定义清楚。

| 术语 | 中文叫法 | 是什么 |
|------|---------|--------|
| **record** | 录制 | 一次 HTTP 请求+响应的完整快照（请求头/体、响应聚合、错误信息）。每条有 `id`（形如 `req_a1b2c3d`）|
| **idx** | 索引 | 同一条 record 的轻量摘要（1-2KB vs record 可超 5MB），UI 列表/DAG 都只读索引 |
| **session** | 会话 | 一次 CC 启动对应一个会话 id（`X-Claude-Code-Session-Id` 头）；与 `~/.claude/projects/` 下 jsonl 文件名一致 |
| **lane**（泳道）| 时序 DAG 的纵列 | 同一会话的请求归一条主线泳道；子代理各占一条实例泳道；辅助调用合一条 |
| **kind** | 请求的语义角色 | 11 种：`main`（主线对话）/ `subagent`（子代理）/ `title`（标题生成）/ `compact`（压缩）/ `security`（安全扫描）/ `count_tokens`（上下文估算探针）/ `quota_probe`（配额嗅探）/ `hook_eval`（StopConditions hook 评估）/ `notify_eval`（走开通知的状态判定）/ `self_prompt`（CC 自己发起的一整轮）/ `other`。每种 kind 的报文形态与识别方法见 [报文解读.md](../methodology/报文解读.md) |
| **turn_start** | 轮次起点 | 用户发了一条新消息（非工具回传）触发的那次请求 |
| **pure_chat** | 纯对话轮 | 整轮零 tool_use——你只是问了个问题、AI 答了，没动手 |
| **ttft** | 首 token 时间 | Time To First Token，从请求发出到上游吐第一个字的毫秒数 |
| **trigger 边** | 派生触发线 | 主线响应里调用了 Task/Agent 工具 → 派生子代理 → DAG 上画一条主线到子代理的虚线 |
| **effort** | 努力档位 | CC 的 reasoning effort（low/high/max），决定模型思考多久 |
| **thinking** | 思考模式 | enabled/disabled/adaptive，与 effort 联合决定官方端点是否接受请求 |

## 第一层：每个视图各是什么

tab 栏有 4 个按钮：**捕获 / 时序 / 分析 / 设置**。另有一个**详情视图**没有独立 tab，
从列表行或 DAG 节点点进去——所以能看到的界面是「4 个 tab + 详情」。
（其他文档提到本篇时一律按这个口径说「4 个 tab + 详情视图」。）

### 1.1 捕获列表（默认视图）

**这是 app 打开后看到的第一屏**，列表展示当日所有 HTTP 请求，倒序排列（最新在最前）。

#### 你看到什么

每行 10 列信息：时间 / 状态色点 / 方法+路径 / kind chip（main 行不显）/ 模型 / 耗时 / token /
ttft / 摘要 / 判定 chip（仅安全审查行）。**列宽固定、逐行对齐**（用 CSS grid 而非 flex——flex 下 kind chip 有无与模型名长短
会推动后面所有列，摘要列起点能在十几行里漂几百像素）。路径与
模型名过长时截断，完整值挂在 `title` 上（悬停可看）。

顶部一张状态卡显示代理状态、路由（`listen → upstream`）、今日计数。状态卡下面可能叠加多条
告警横幅（cc-switch 警告 / 外部接管 / 孤儿恢复 / 落盘失败 / 体检 error/warning）。

日期行**左侧**在导入过别的机器的录制时会多出一条**来源切换条**（没导入过就完全不渲染）：
`本机 | ● laptop`。选中外来来源时那颗实心点与高亮边框是有意的——把别的机器的证据当成本机
事实读，排查会直接跑偏，所以"现在看的不是本机数据"必须一眼可见。切换来源会重取日期与列表
（外来录制没有"今天"可跟，跨天自动跟随也随之关掉）。

日期行右侧（与"清理"并列的工具区）有一个**失败聚合按钮**：`● 失败 N · M 组`，
**当天没有失败时不渲染**。点它在日期行下方就地展开面板，每组一张卡：

- 头部：`×次数` + 错误类型 + HTTP 状态 + 受影响的请求类型（`主线×19` / `标题×19`…）
- 中部：**上游自己给出的错误原文**——这是整块面板的重点，上游已经替你诊断过一次
- 请求侧字段：`effort=max` / `model=[glm-5.2, glm-5v-turbo]` 这样的小胶囊。
  **加粗的是"全组一致"（可能就是病因），方括号列表是"跨多个值"（可以排除这个字段）**
- 底部：起止时间、涉及几个会话、样本 id（点一下直接跳到那条的详情）

一天几千条失败会被压成几组人话——实测 2719 条 → 7 组、0.09 秒。这块的价值不在"看到有失败"
（列表里的红点已经说了），而在**看出这些失败其实是同一个原因**。

> **它为什么是个小按钮，不是横幅**：260801 首版把它做成状态卡下方的整宽横幅，当天就降级了。
> 它是**归纳**不是**告警**——真告警说的是"现在有件事正在坏"（录制没落盘、代理被绕过），
> 不看会损失数据；失败聚合是查问题时才要的分析视角，平时不看没有损失。把归纳摆成告警的位置，
> 既占掉主内容的首屏高度，又会**稀释真告警的分量**：一个天天都在的横幅，人第三天就不看了，
> 那条"落盘失败"的红条会跟着一起被无视。同 2.2 节体检铁律里那句"第二次误报之后横幅就再没人看"。

#### 数据从哪来

- 列表数据：`GET /api/captures?date=YYYY-MM-DD` → 返回 `{date, total, items[], dates_available}`
- 每个 item 是 idx 摘要（剥离了 DAG 分类原料等私有字段）
- 状态卡：`GET /api/proxy/status`（5 秒轮询）+ `GET /api/health/config`（体检）
- 失败聚合：`GET /api/diagnose/errors?date=…&limit=50`（切日期时取一次；LIVE 期间只在**新到的
  增量里确实有失败**时才防抖重取，否则一天几千条成功流量会把它变成 800ms 一次的全量扫描）
- 实时增量：`GET /api/captures/stream`（SSE，新请求或请求完成时推摘要）

#### 反思：信息密度对人不友好

> 一行塞 10 列等宽字体多色 chip，对工程师是信息密度，对非工程师是噪音。
> 尤其是 token 列 `1.2k→800 (+1.5k cache)`——cache_read 是什么、为什么这么高，没有解释。

但**状态卡做得很对**：`http://127.0.0.1:5051 → https://...` 的端到端路由让人一眼看到代理正在
转发到哪。这是审计的基本盘。

#### 容易踩的坑

- **清理按钮二次确认是 4 秒倒计时**：第一次点展开下拉菜单，选"清除"后按钮变红脉冲 4 秒，
  在窗口期内再点才执行；分神就以为"点了没反应"。这是防误删的设计，但缺乏提示。
- **下拉菜单里的五条不是同一类动作**（260825）。前两条「压缩」什么都不删——它把过去的天
  原地压实（实测 20~34x），压完照常翻、照常看详情，可以 CLI `uncompact` 还原回去；
  中间「归档为单文件」产出可拷到别的机器的 `.ccwa`，也不删原录制；只有后两条红色的会真的
  删数据。**只有红色的才是不可逆的**，这条区别在文案里写死了，别靠记。
- **压缩/归档没有进度条**，一天几百 MB 要几十秒。期间按钮 disabled 并显示"处理中…"——
  这是有意的最低限度反馈（异步任务从用户动作到状态可见之间不许有裸窗），但确实看不出进度。
- **告警横幅只在捕获 tab 可见**：DOM 全在 `view-list` section 内，切到设置/时序就隐藏。
  打开设置时其实也跑了一次体检（refreshHealth），但切过去看不到结果——见下面 1.4。

### 1.2 详情视图（无独立 tab）

**点列表任一行进入**，左右两栏 grid 展开单条 record 的完整请求与响应。

#### 你看到什么

顶部面包屑是两栏共用的：id + method+path + 状态 chip + timing（起止/total/ttft）。两栏各自
以「栏头 + 元信息卡」开场，且**两栏的元信息卡等高**——下面每一块因此左右齐平（260730 修：请求侧
原先是个裸 chip 行，比对面的卡片矮 27px，两栏从第二块起全程错开）。

- 左栏（请求）：元信息卡（model / stream，均来自请求体）→ 安全审查卡（仅 security 请求）
  → 折叠的 Headers → 折叠的 System blocks（每块标注角色）→ 折叠的 Tools → 默认展开但只显
  最近 3 条的 Messages
- 右栏（响应）：元信息卡（status / stop_reason / ttft / total，均为响应侧字段）→ 默认展开的
  响应 Headers（wire-only 字段高亮）→ Usage 四宫格（input/output/cache_read/cache_creation，
  只给原始 token 数，**不折算金额**）→ Content Blocks（thinking/text/tool_use 分段显示）
- 失败时多了 Error dcard（kind/status/detail/body_snippet）

> `model` / `stream` 在请求侧不是笔误：它们是请求体里 CC 指定的参数，本工具**不记录响应侧的
> model 字段**（实测上游未回）。不提供成本估算——按刊例折算对走第三方网关的用户不准。

#### 数据从哪来

`GET /api/captures/<rid>?date=YYYY-MM-DD` → 完整 record（含 request.body 的 system/tools/
messages，response.content_blocks 全量）。底层用 idx 的字节偏移直接 seek 到主文件对应位置。

#### 每段大文本的工具条

每段长文本（system block / message / content block）右上角有一组工具按钮：展开 / 复制 /
格式化（JSON 美化或 markdown 渲染）/ **翻译**（调 `/api/translate` SSE 流式）/ **AI 解读**
（调 `/api/explain`，带防注入隔离）。

翻译与解读的结果块顶部可能出现一条金色提示，说明**这次输出为什么到此为止**（260801）：

| 提示 | 含义 | 怎么救 |
|---|---|---|
| 原文过长，只发送了前 N 字符 | 本工具在发出去之前砍的（成本护栏）。上限**不写死**：设置 → 翻译/AI 的「最大输入字符」可调（260825 起，单位字符——截断提示报的也是字符，对得上） | ✅ 调大「最大输入字符」后重试 |
| 输出到达上限被截断（当前设置 N） | 上游 `finish_reason=length` | 也许——调大「最大输出 tokens」；上游模型自身也有输出上限，填得再大也超不过它 |
| 上游内容审查中断了输出 | 上游 `finish_reason=content_filter` | ❌ |

没有这条提示 = 模型自然说完了。**这条提示之所以必要**：三种成因单看界面长得一模一样
（都是文本停在半截），没有它，用户改了 `max_tokens` 也无从判断有没有生效。

> 复制功能背后是一段隐形工程：因为 WebView2 把原生右键菜单绑在 debug 开关、macOS WebKit
> 干脆没 Edit 菜单，复制链路全靠前端自绘右键菜单兜底。正文默认可选，只有按钮 / 标签页 /
> DAG 节点这类交互控件不可选——这是开发者门槛，对最终用户透明。

### 1.3 时序 DAG（核心可视化）

**这是项目最复杂的视图**，画一张时序有向图：纵轴是泳道（分组），横轴是时间。

#### 你看到什么

- **节点**（dag-node）：一条 HTTP 请求。卡内：时间 / kind chip / 模型 / 耗时 / token / 摘要。
  安全审查节点的摘要显示「审查：<待判定动作>」（与列表行同一套格式化——直接显示响应正文
  残片的话，落到眼里的会是 `<severity>8`、`<block>yes</block><category>…` 这种最没信息量的片段）
- **泳道头**：lane 颜色 + 名称（主线 N）+ 计数 + 短码
- **泳道配色**：主线按首见顺序取六色色板（**每套外观各有一份色板**，
  深色底用提亮版、两套浅色底用加深版——同一组色值不可能同时落在炭底和纸面上还都过 AA）；
  **子代理 = 派生方同色混白淡化**，
  嵌套派生（子代理再派生子代理）逐级更浅，同族一眼可辨；派生方没录到的子代理
  （Workflow 派生无 trigger 边）保持蓝色——蓝色的含义是「派生方不在图上」
- **三种连线**：
  - **seq**（同 lane 实线）：同一泳道里前后相邻的请求
  - **trigger**（粗虚线带箭头）：主线派生了子代理
  - **near**（点线）：辅助调用挂到**它服务的那一方**。默认是所属主线（按 session id 精确挂接
    ——辅助请求也带会话头；挂不上才退回时序最近的主线）；**安全审查若审的是子代理那次工具调用，
    就挂到那条子代理泳道**（260902，判据是请求正文里被审 agent 的 transcript）
- **按轮折叠（260802，默认开）**：main / 子代理泳道每轮只画一张**轮卡**——
  卡上是「**你那轮说了什么**」+ 这轮派生的子代理徽章 + 辅助调用计数（🏷标题 / 🛡安全 / 🔢计数）。
  子代理徽章的**文字颜色按泳道色亮度算**（`fgOnHex`），不写死白字——子代理色是派生方色兑 45% 白，
  三套外观下都是浅色，白字实测只有 1.6:1。
  子代理泳道的轮卡写「派生：」而不是「你：」——那是派生方给它的 prompt，不是人说的话。
  点卡片展开该轮逐条请求，点子代理徽章直接聚焦到那条泳道。
  失败在轮卡上是 ⚠N（几条失败），只有**整轮全挂**才整卡染红——一轮 31 步里有 1 次瞬时 429
  与整轮失败是两件事，一律染红等于把红色用废（实测一天 68 轮有 29 轮含至少一次失败）。
- **辅助聚合卡**：折叠态下，有归属（near 边）的辅助**按轮**收成一张聚合卡——立在 aux 列组首
  的时间槽，边线/计数章用归属方的泳道色，near 虚线从那张轮卡连过来。
  点卡展开该轮全部辅助（展开后首条带「▴ 折叠」收回）；展开某一轮，该轮的辅助也单独回到 aux 列。
  260802 首版按**主线**分组，一天只有泳道数张卡、点开一次展开全天 90+ 条，没有中间档；
  260809 粒度收紧到轮。子代理的轮同样有自己的聚合卡（260902 起安全审查可归子代理）。
  （上一版「辅助全折进轮卡徽章、aux 列整列消失」实测把辅助维度弄丢了：当天 124/124 全有归属，
  列没了、near 边全成自环——辅助维度的可见性不能靠"先猜到在哪一轮"。）
  ⚠️ **没有归属主线的辅助不进卡、照常单条**：那是 near 边没挂上的（本会话主线没被录到 / 跨天截断），
  藏了就是静默丢数据。
- **三档节点视觉**（展开后才成立）：默认卡片=轮次起点 / mid 细条=工具循环步 / chat 虚线带💬=纯对话轮
- **错误折叠**：连续 ≥2 个错误节点折叠成 "ERR RUN ×N" 红卡，点击展开
- **两个折叠开关不是一回事**：「按轮折叠」是**聚合**（把一轮的请求收进一张卡），
  「隐藏工具循环步」是**过滤**（把中间步整条藏掉）。前者回答"这轮我说了什么、发生了什么"，
  后者回答"别给我看这么多条"。展开某一轮之后，后者对该轮内部仍然生效。

> **为什么换聚合单位**（260802 用户提的问题）：`hideMid` 解决的是"太多"，不是"看不懂"。
> 过滤之后剩下的仍然是**请求**——卡片主体是模型回答的前 60 字，而人回溯时的检索键恰恰是
> 自己说过的那句话。轮才是对话的语义单位。

#### 数据从哪来

`GET /api/dag?date=YYYY-MM-DD` → `{nodes[], edges[], lanes[], turns[]}`。后端
`classifier.build_dag` 从索引记录构建：
- 每个 node 含 kind/lane/turn_start/tool_uses/pure_chat 等分层原料，加所属轮 `turn`
- lane 含 kind/main|subagent|aux/count/session_id
- edge 含 from/to/type
- **turn** 含 user_text / steps / errors / subagents / aux（见 [API契约.md](API契约.md) 的
  `/api/dag` 段）。前端只消费不重算——分轮判据与归属推断都在后端一处

#### 反思：派生关系画了线但没画"派生什么"

> DAG 上的 trigger 边（粗虚线带箭头）告诉你"主线 N 派生了某个子代理"，但子代理节点上
> **没有可读标签告诉你派生 prompt 是什么**。后端 `task_prompts` 字段已经算好了——
> 主线响应里 Task/Agent 工具的 input.prompt 全文都存在，子代理首条 user 也对齐了——
> 但 UI 没渲染。你看到 5 个 Explore 子代理，却不知道各自被派生去做什么任务。

这是 UI 与后端能力之间最宽的一道缝——数据齐了，界面没接。

#### 泳道头的短码语义

主线泳道头**显示"主线 N"序号**（按首见时间排 1, 2, 3…），副标签才显示 `session_id`
前 8 位 hex 短码（能对上 `~/.claude/projects/` 下的 jsonl 文件名）。**260801 起，新录制的子代理
泳道键 = CC 官方实例 ID**（`X-Claude-Code-Agent-Id` 头，`agent-a1b2c3…` 形），泳道头短码能直接对上
`~/.claude/projects/<项目>/<会话>/subagents/agent-<id>.jsonl` 的子代理完整对话文件名；老录制
（07-31 前的 CC 没这个头）仍是 `md5(派生者|prompt)` 短码，对人无意义。辅助泳道头仍是 `aux`。

#### 交互细节

- **hover 节点无 tooltip**（只有派生关系的 assoc-dot 圆点带 title）——为什么这卡是金色、
  为什么连这条虚线，全靠图例+颜色推断

  一起隐藏，下拉里这些行标注「随 XX 隐藏」；想单独看某个子代理，再勾它一下就单独显示

  上游配置历史修的是这个病：录制期间 BASE_URL 是本机地址，cc-switch 此时"保存当前为 profile"
  会把这个地址固化进该供应商；日后切回来，CC 指着一个早已关掉的本地端口，第三方 token 与官方
  订阅 OAuth 全部失效，而配置表面上"看着是好的"（有 URL 有 token），极难认。下拉里是最近 5 套
  **真实上游**（本机地址一律不记），选一条点「一键修复」即把整组 `ANTHROPIC_*` 对齐回去。
  三个设计要点：**默认选中 `token_match` 那条**（凭据与当前相同 = 同一供应商的干净版本，用户
  不必自己认哪条对应谁）；**订阅态显示为「官方订阅（无 BASE_URL）」**，还原时是删键而不是写
  任何 URL；**代理录制中该行不报病态也拒绝修复**——那时本机地址本就是正常的。
- **LLM 模型**：API Key（密码+眼睛切换）/ Base URL / Model / Temperature / Max tokens /
  **最大输入字符**（单轮翻译/解读的原文上限，260825 前写死 20K）/ **分析对话上下文上限**
  （分析页每轮注入的快照摘要上限，同样 260825 前写死 20K——两个都以**字符**为单位：客户端
  算不出 token，而截断提示报的就是字符，配置项与提示同单位才所见即所得）/
  翻译目标语言 / AI 解读提示词 textarea / 测试连通按钮
- **给 AI 用**（260801）：一句可复制的话（含本机实际端口）、说明书端点地址、无界面模式命令。
  把那句话粘给你自己的 AI，它就能读到完整用法并驱动本工具——**不需要这个仓库**，
  说明书打包在产物里
- **关于**：版本 / 数据目录 / 日志路径 + **检查更新与就地安装**（260808）

  点「检查更新」后，若有新版本，下方展开更新面板：版本对比与安装包体积 → 「下载」（带进度条，
  可取消）→ 校验通过后变成「安装并重启」。**安装要点两次**（第一下变成「确认安装？」），
  与「按标签批量删快照」同级——这一步会替换掉正在运行的程序。面板底部一行小字交代校验情况：
  比对过 release 的 SHA-256 清单就说比对过了，没有清单就**明说没有**并给出实测值。

  三种不能就地安装的处境各说各的原因，**不给一句笼统的"不支持"**（那会被当成坏了，
  用户下一步就是自己去手动覆盖文件）：源码运行 → 让你 git pull；正在录制 → 让你先停代理
  （**不代劳**，停代理要写你的 settings.json）；目录不可写 → 回落成"已下载好，打开所在文件夹
  自己换"。macOS 一律不就地替换，只在访达里指出新版本。

### 1.5 分析（快照对比 / 录制分析agent行为，260808）

两个可切换子页，各自一块**白板**——备份下来的东西像贴纸一样贴在板上，点选贴纸产生动作。
**快照的入口不在这一页，而在详情页的右键菜单**：备份是"看到一段东西、随手存下来"的动作，
得发生在你正读它的地方。

#### 你看到什么

- **子页 A 提示词对比**：白板上只有**提示词贴纸**（暖色纸）。点两张 → 左（金）右（绿），
  下方立刻出精确 diff：工具条（翻译左/右侧原文、AI 对比分析）→ 结论先行（完全相同 /
  只差日期这类必变部分 / 有实质差异）→「隐蔽差异」专区 → 元数据差异表 → 正文逐行 diff。
  **隐蔽差异每一行右侧带行号按钮**，点一下跳到正文里出现的位置并闪一下——只报数量不给位置，
  等于让人在几千行里找一个肉眼看不见的字符。
- **子页 B 录制分析agent行为**：白板上只有**录制贴纸**（冷色纸），纸面直接写着模型、消息数、思考字数。
  **点一张 = 分析这条录制**（可得性横幅 + 多源指令清单 + 轮次骨架，点某一步展开思考原文），
  再点另一张直接换分析对象（260826 起单选；此前的"点两张按面对比"从 GUI 移除，
  两条录制按 system / 工具集 / 对话历史对比只剩 `GET /api/snapshots/diff?face=` 这条 API 通道）。
  轮次骨架有**列表 / 八视图**两档（260828 起，八视图换掉了原来的"树"档）。
  - **列表**：按轮组织的步骤流，轮头四问（你要什么 / 这轮在解决什么 / 结果 / 风险）+
    步级三段简报（做了什么 / 为什么 / 得到了什么），点某一步展开思考原文。
  - **八视图**：同一条录制的八种读法——状态快照序列 / 物料血统 / 验证矩阵 / 阀门与回路 /
    能耗与方差 / 最优轨迹 / 物料生命线 / 最优时序图。地基是**全部主线请求的 blocks 并集**
    （不是单条最长请求——autocompact 剪掉的前半段会捞回来）。事实由程序算、语义由模型写，
    事实格在渲染前被程序盖掉，模型改不了。当日数据已归档（`.ccwa`）的录制会**如实说出不了图**，
    而不是渲染半截 run。
    它实现上是一份独立文档（可单独打开：`/api/snapshots/<sid>/trajectory?format=html`），
    但嵌进来时**看不出是 iframe**：背景透明、无第二个顶栏、高度跟着内容走（全页一条滚动条）、
    外观跟着主界面即时切换。260829 之前它是一块自带黑底与滚动条的面板——见开发约定第九节。
  顶栏另有两个复制按钮（给 agent 的指令 / 给任意 AI 对话框的提示词）。
- **子页 B 底部：软件内 AI 分析对话**。选中一条录制后出现，用设置页配的那个低成本模型，
  可以连续追问。预设问题**按可得性档位切换**——有思考链才问"考虑过哪些分支"，
  没有思考链只问"哪儿在反复"，因为后者无从回答，硬问就是在诱导编造。
  对话**落盘跟着快照走**，外部 agent 也读得到（`GET /api/snapshots/<sid>/chat`），
  两条分析路径不互相隔绝。Ctrl+Enter 发送（裸 Enter 留给换行——提问经常要分行写）。

贴纸可拖动，位置**跟着快照存**（不是存在配置里：贴纸摆在哪儿是用户对这批快照的信息组织，
快照删了它就该一起消失，而不是在配置里留一条指向不存在快照的孤儿坐标）。「整理贴纸」
**按备份时间重排**（不只是归位——只归位的话，贴纸本来就在默认位置时点了毫无变化，
用户只会觉得按钮坏了）。贴纸 hover 出现 × 可删除，删除走内联二次确认。

页头「清理…」是**批量出口**：按类型/标签/日期筛，**先预览命中几条、能腾出多少，再确认删除**。
快照永不自动清理是有意的（用户显式保存的东西不该被后台删掉），代价是会堆——手动出口因此必须
存在；而按标签批量删不可撤销，一步到位的按钮迟早误伤。

#### 数据从哪来

`/api/snapshots*` 全家（契约见 [API契约.md](API契约.md) 的「快照」一节）。快照存
`~/.cc-wire-analyzer/snapshots/`，**不受 `retention_days` 自动清理**——与「归档后清除」
（那个会删原录制）是两回事，别混。压实（compact）又是第三件事：它只改存储形态，不删任何
东西。三者的边界见 [开发约定.md](开发约定.md) 第六节「存储分层」。

#### 反思

- **对话区没有"引用某一步"的动作**。现在追问某一步只能自己写"第 12 步"，而屏幕上就摆着
  那一步的骨架行——点它直接把步号带进提问框，本该是顺手的事。
- **子页 A 的提示词快照还不能开对话**。后端 `/api/analyze/chat` 已经支持提示词快照
  （上下文 = 元数据 + 正文），只有界面没接——两段提示词的差异分析目前仍是单轮出结论。
- **清理面板不能按"内容相同"筛**。重复备份是允许的（同一段文本、不同供应商，本身是有价值的
  事实），但真堆起来时，"把内容完全相同且元数据也相同的合并掉"会比按日期删更有用。

#### 陷阱

- **右键菜单里的"备份这段提示词"只在带来源锚点的块上出现**（system 各块、messages 的文本块）。
  在别处右键只会看到"备份当前录制"——这不是 bug，是没有可靠来源就不编一个。
- **两块白板不通用**：提示词贴纸只在子页 A、录制贴纸只在子页 B。想比较两条录制得去子页 B
  选两张，不是在 A 里找。
- **`norm_equal` 比 `equal` 更值得先看**。CC 的提示词里含当天日期，`equal` 几乎永远为假；
  真正该问的是"除了日期这类每次必变的部分，到底有没有变"。
- **两段本就不同类的提示词也能比**（主线 vs 子代理、主线 vs 标题请求），页面会给可比性提醒
  但不拦——满屏红色时先看那条提醒，再判断是不是真的"提示词大改了"。

## 第二层：界面之外还要知道的事

后端算出来的东西比界面摆出来的多。这一层逐条说清**每个能力的入口在哪**——有的入口很深
（体检只在捕获 tab 有横幅）、有的语义值得先读一遍才用得对（失败聚合的单值/列表）、

### 2.1 失败聚合（diagnose）：入口在捕获页，语义值得先读一遍

> **这是一天里几千条失败压缩成几句人话的能力**：把 `(err_kind, status, 错误消息指纹)`
> 相同的失败归一组，每组摆出请求侧字段（model/effort/thinking/stream/max_tokens）。
> 一次实测把 2719 条失败归并成 7 组，0.09 秒完成。

每一组的样子：

```
err_kind: upstream_4xx
status:   400
message:  effort 'max' is not supported when thinking is disabled
count:    19
first_ts: 2026-07-18 10:22:01
last_ts:  2026-07-18 16:14:33
kinds:    {title: 19}              ← 全是标题生成请求
sessions: 1
req_fields:
  effort:    max                   ← 单值：全组都是 max（可能病因）
  thinking:  disabled              ← 单值：全组都是 disabled（可能病因）
  model:     [glm-5.2, glm-5v-turbo]   ← 列表：跨多种模型出现（排除模型当因）
```

`req_fields` 单值/列表语义是这套设计的精髓：

- **单值** = 全组在这字段上完全一致 → **可能是病因**
- **列表** = 跨多种值都出现 → **排除了这个字段当因**

光看 `message: effort 'max' is not supported when thinking is disabled` 加 `req_fields:
effort=max + thinking=disabled`，病因一目了然——比你逐条点开 19 个红卡看错误快几个数量级。

#### 怎么访问

```bash
# 界面：捕获页状态卡下方的「本日失败 N 条 → 归并为 M 组」折叠区

# CLI（给 agent 用，但人也能跑）
uv run python src/cli.py errors
uv run python src/cli.py errors --date 2026-07-18 --limit 50

# API
curl "http://127.0.0.1:<port>/api/diagnose/errors?date=2026-07-18"
```

#### 为什么这一节值得存在

失败聚合曾经是本章最宽的一道缝：后端把一天几千条失败压成几组只要零点几秒，而这个结论
有六周没送到人眼前——不是难度问题（前端约 200 行、后端零改动），是**"能力做完了就以为交付完了"**。
入口 260801 补上了，这一节留着，是为了下次再出现"后端算好了、界面没接"时能早一点认出来。

### 2.2 配置体检（doctor）：入口隐蔽 + 跨 tab 隐身

8 条只读规则，启动代理前跑一遍，error 级拦启动（留 `force=1` 逃生门）。

| # | code | severity | 检查什么（一句话） |
|---|------|----------|----------|
| 1 | `half_switch_to_subscription` | error | BASE_URL 指第三方但没 token，OAuth 却在 → 切了一半 |
| 2 | `dead_port_leftover` | error | BASE_URL 指本机端口但没人听 → 代理死了/残留 |
| 3 | `self_reference_state` | error | BASE_URL 指本实例端口但不在 patch 态 → 会自指递归 |
| 4 | `oauth_expired` | error | OAuth 过期 + 用订阅模式 → 会 401 |
| 5 | `effort_level_conflict` | warning | 顶层 effortLevel 与 env 矛盾 → 顶层那个无效 |
| 6 | `effort_max_rejected_upstream` | warning | effort=max + 官方端点 → 标题生成等静默 400 |
| 7 | `oauth_expiring_soon` | info | OAuth 还剩 < 1 小时过期 |
| 8 | `token_overrides_oauth` | info | 同时有 OAuth 和 token → token 优先（多半你故意的）|

> **自检**：加/改 doctor 规则必须同步 `src/doctor.py` 的 `check()` 规则元组（真源）+ `dc.*`/`dcfix.*` 三语 i18n + 本表，三处缺一就是惯犯 bug ③。

#### 入口隐蔽在哪

- **没有独立 tab**：体检结果通过捕获 tab 顶部的横幅 + 抽屉展示
- **error 级有红横幅**，warning 级有黄横幅，**info 级只进抽屉**（无横幅提示）
- **抽屉默认收起**，需点"查看详情"展开
- **打开设置时虽然跑了体检但 DOM 在 captures section**——切过去看不到（见 1.4 反思）
- **i18n 已覆盖全部 8 条规则**（`dc.*` 三语 zh/en/ja）；不再回落英文 code

#### 反思：体检结论还有几个隐藏字段

`/api/health/config` 返回的不止 `issues[]`，还有：
- `intent`（subscription/third_party/unknown）：体检认为你想用哪种认证方式——**UI 从未显示**
- `scope` + `scope_note`：体检读的是 settings.json 文件，不是 CC 进程环境——**UI 从未显示**
  （这条边界很重要：你改了 settings.json 但 CC 没重启，体检看到的还是旧值）

### 2.3 派生关系（trigger 边 + task_prompts）：画了线没画内容

DAG 上 trigger 边告诉你"主线 N 派生了某个子代理"，但**派生 prompt 全文藏起来了**：

- `idx.task_prompts`：主线响应里每个 Task/Agent 工具的 input.prompt（前 1000 字）——**UI 不显示**
- `idx.first_user_task`：子代理首条 user 剥掉 `<system-reminder>` 后的前 1500 字（≈派生 prompt 原文）
  ——**UI 不显示**

结果：你看到 DAG 上有 5 个子代理节点，但要知道它们各自被派生去做什么任务，必须点进每条详情
自己翻 messages[0]。

靠 task_prompts 对齐判别子代理实例 lane 时，**并行派生 + 同类型 agent + 模板化 prompt**
的组合曾让多个子代理挤到一条泳道上。现在只剩一种边界情形：**派生 prompt 前若干百字完全相同**
的并行同类子代理仍可能合并（留待双向匹配策略）。但 task_prompts 在 UI 仍不可见——如果
可见，用户能一眼看出剩余的撞车边界情形。

### 2.4 响应头：wire 层最值钱的字段

详情视图的"响应 Headers"区域**默认展开**，wire 层独有的关键字段（`anthropic-ratelimit-*` /
`request-id` / `anthropic-organization-id` / `x-should-retry`）以**加粗 + 品牌色高亮**，并附提示
"仅在 wire 层可见，CC jsonl 不记录"。这些是 CC jsonl 永远记录不到的字段：

| 响应头 | 含义 | 审计价值 |
|--------|------|----------|
| `anthropic-ratelimit-tokens-remaining` | 还剩多少 token 额度 | 提前知道会不会撞限流 |
| `anthropic-ratelimit-requests-remaining` | 还剩多少次请求额度 | 同上 |
| `request-id` | 上游分配的请求 id | 跟上游对账/报 bug 时用 |
| `anthropic-organization-id` | 你所属的组织 id | 验证用的是哪个账号 |

代码注释作者自己写道："这里恰恰是 wire 层最值钱的信息"——原先默认折叠让新手不知道，现已摊开。

### 2.5 子代理身份判别信号：完全在 UI 之外

决定一条请求是不是子代理、属于哪条实例泳道的核心信号：

- `is_subagent`：system block[0] 计费头的 `cc_is_subagent=true`（**权威位**，260725 实测确立）
- `entrypoint`：`cc_entrypoint`（cli/sdk-cli/sdk-mcp，区分交互 vs headless vs MCP）
- `agent_fp`：system block[2] 的 md5（区分 Explore/Plan/general-purpose）
- `session_id`：CC 会话 id（子代理复用父的，只能当 lane 键）

这些字段全在 idx 里、API 也返回，但 **UI 完全不显示**。当泳道判别出问题时（比如本次撞车
bug），用户只能用 `tools/lane_probe.py` 才能摊开看——非程序员根本无从下手。

### 2.6 API 浏览面：主界面之外的第二个页面（260825）

`/view` 和 `?format=html` 不在那五个 tab 里，**主界面上也没有入口**——它是给"想核对 AI 那一侧"
的人准备的独立页面，只能靠地址栏进去。之所以单独做一页而不是塞进设置：这一页渲染的是
**API 的原始返回**，而不是被界面加工过的视图；把它放进主界面，人会分不清眼前这份是"工具
整理过的"还是"AI 真拿到的"，而这个页面存在的全部意义恰恰是后者。

| 你想确认 | 打开 |
|---|---|
| agent 读到的说明书长什么样 | `/api/ai-guide?format=html` |
| agent 查列表拿到的是什么 | `/api/captures?date=…&format=html` |
| 一共有哪些端点、各是干什么的 | `/view` |

三个容易踩的点：

1. **它不改 API**。不带 `format=html` 时响应逐字节不变（有自测守着）。所以在这一页上看到的
   就是 AI 拿到的，不存在"给人看的版本"和"给 AI 看的版本"两份。
2. **列表里灰掉的行是有意的**：需要路径参数的端点点不了；`/api/captures/stream` 是 SSE 长
   连接、`/api/update/check` 会联网，两者**列出但不给链接**并写明原因——不给会挂住浏览器的
   链接，不算"提供了入口"。
3. **超过 4 MB 的响应不渲染**，页面会写明字节数与上限并给出原始 JSON 链接。它宁可不给，
   也不会截一半让你以为看全了。

## 第三层：语义 token 速查（改界面之前先读这一节）

三套外观不是三份样式表，是**同一批语义 token 的三份取值**。组件只引用 token，
不写死颜色——写死的那一刻，它就在等着另外两套配色把它变成隐形字（曾经的
子代理徽章 `color:#fff` 落在浅色泳道底上只有 1.6:1，就是这么来的）。

**这一节只讲「什么时候用哪个」，不列取值。** 取值是 CSS 的职责，抄进文档就必然漂移；
`:root` 的注释里写着每档的实测对比度，那才是真源。

### token 分几族

| 族 | 代表 | 什么时候用 |
|---|---|---|
| **表面** | `--bg-canvas` `--bg-card` `--bg-soft` `--bg-softer` | 由远及近四层：画布 → 卡片 → 卡内分区 → 卡内的卡。**别跳级**，跳了层次感就塌 |
| **文字** | `--apple-text` `--apple-text-secondary` `--apple-secondary` `--text-tertiary` `--text-faint` | 由强到弱五档，每档都按 AA 校过。**小于 12px 的字不许用后两档** |
| **强调** | `--accent` `--accent-deep` `--gold-text` `--gold-text-2` | `accent` 是块状填充（按钮/选中），`gold-text` 是**落在浅底上的文字**——两者在浅色外观下差很远，用反了就是对比度事故 |
| **落在强调色上的前景** | `--accent-contrast` `--chip-*-fg` | 凡是「背景用了强调色」，前景必须从这一族取，不许写 `#fff`。背景是**算出来**的（如子代理泳道色）就用 `fgOnHex()` 按亮度选 |
| **状态** | `--ok` `--err` `--warn` `--info` + `--ok-soft-*` `--bg-error-soft` | 实心那组给图标与文字，`-soft` 那组给底色。**红色只留给真失败**——用滥了它就不再是信号 |
| **描边与分隔** | `--border` `--border-soft` `--card-border` `--row-border` | 前两个是实色描边，后两个是半透明叠加（跟着底色走，深浅通吃） |
| **阴影与高光** | `--apple-shadow-sm/-/md/lg` `--apple-highlight` | 四档对应"贴着/浮起/悬停/弹出"。**高光要和阴影配对用**——只有阴影没有内高光，卡片看着是凹的 |
| **交互态** | `--focus-ring` `--node-hover-ring` `--selection-*` `--input-focus-bg` | 键盘焦点一律走 `--focus-ring`，别各写各的 |
| **终端面** | `--terminal-bg` `--terminal-code-bg` `--terminal-text` | 详情页的报文区：凹陷的深色面 + 等宽字。报文是"原始字节"，视觉上要与解读区分开 |
| **主题无关** | `--font-*` `--radius-*` `--apple-transition` | 三套共用，单独放在第一个 `:root` 块里 |

### 加一个新 token 的规矩

1. 先在上表找现成的——**能复用就别新增**，token 越多，下一个人挑错的概率越大。
2. 真要加：加进**深色块**，然后 `classic` / `light` 各给一份取值。
3. 跑 `uv run python tools/doc_audit.py`：漏了哪套、或者加完没人用，它会报出来。
   漏取值不会报错也不会白屏——那套外观只是静默落回深色的颜色，某个组件在纸面上变成一块深色。
   **这正是需要机器查而不是需要人记的原因。**

（阴影/圆角/间距的取法，以及"为什么装饰要做精而不是做减法"这类判断，属于开发约定，
在 [开发约定.md](开发约定.md) 第九节「前端约定」。）
