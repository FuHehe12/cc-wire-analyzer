## 引子：这个工具最不能容忍的失败，不是录不下来

一个抓包工具录漏了几条请求，是缺陷；**把被抓包的对象弄挂了，是事故**。

CC Wire Analyzer 通过改写 `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL` 把自己插进 Claude Code
和上游之间。这意味着它随时可能让用户的 CC 完全不能工作——指向一个已经退出的代理端口、指向
自己造成无限递归、或者拿过期的备份覆盖掉用户刚配好的新端点。这些不是假想，**每一条都真实
发生过**，都能在下面的不变量清单里找到对应的那一条。

所以这个项目的优先级是反直觉的：

> **录制失败不许阻塞转发**——录不下来是本工具的损失，转发断了是用户的损失。

理解了这一条，后面所有看起来"过度防御"的设计就都讲得通了：为什么恢复要六重、为什么自测
不许碰真配置、为什么索引要带版本号、为什么 `except: pass` 是禁令。这份文档就是把这些机制
和它们各自防的那件事一一对上。

## 一、十条安全不变量（绝不破坏）

每条背后都有具体场景，**都是撞过才写下来的**。

### 1. 代理路径只改 `ANTHROPIC_BASE_URL` 一个字段

代理的 patch/restore 路径对 settings.json 只动这一字段。恢复用「改回原值」（原本无键则删键），
**不用整文件回滚**。

> 260807 加了限定词「代理路径」：新增的**用户显式还原**动作会写整组 `ANTHROPIC_*`（见不变量 9）。
> 这条防的一直是「代理**在用户背后**动别的字段」这种隐式副作用，不是按字段数量一刀切——
> 条文按动作分类，两类动作各有各的边界。

*防什么*：代理期间用户、CC 自己、外部切换工具都可能改别的字段，整文件回滚等于偷偷撤销别人
做的事。连行尾符都要原样保留——Windows text mode 把 LF 转成 CRLF 会污染用户的 git diff。

### 2. 停止/恢复要万无一失（六重）

窗口 `closing` 事件 + GUI `finally` 块（`os._exit` 跳 atexit 前手动调 `_safe_restore`）+ `atexit` + signal + excepthook + orphan-marker，六道都要在。另：`cli.py restore` 是用户主动调的命令行兜底，不属于这六道自动恢复——但真出事时它能手动救回来。

*防什么*：CC 被留在指向死代理端口的状态——那时用户的 CC 完全不能工作，而且**看不出是本工具
造成的**。

两个平台细节，都是踩出来的：

- `closing` 是 pywebview **唯一同步派发**的关闭事件（`Event(self, True)`）。macOS 的 Cmd+Q /
  红点关窗走 `NSApp terminate` → C 层 `exit()`，**绕过 Python 的 finally 与 atexit**，只有
  `closing` 能兜住。
- `closed` 是异步派发（后台线程），退出竞态下不可靠，**别拿它做恢复**。

### 3. 只撤销我们还能证明是自己做的那一笔

恢复前必须比对 settings.json 的当前值是否仍等于我们 patch 进去的地址（marker 记的 `listen`）。
不相等 → 用户或外部工具已自行改动，**一律不碰文件**，只清 marker。

*防什么*：陈旧 marker 拿过期信息覆盖用户的新配置。最严重的一种：`had_key=false` 的陈旧
marker 会**直接删掉**用户刚设好的 BASE_URL。

### 4. 所有上游渲染内容过 DOMPurify

marked.js 的输出必须消毒。

*防什么*：存储型 XSS。录制里可能有恶意脚本，被 markdown 渲染进前端就能执行——而录制内容
完全不受本工具控制。

### 5. `date` 类型的 API 输入要校验

`YYYY-MM-DD` 格式 + 语义都要验。

*防什么*：路径穿越。capture 的清理/归档路径直接用 date 拼文件名，`../../` 能任意删读文件。

### 6. AI 解读的隔离定界符硬编码

用户内容之外的定界符头尾**不可被自定义 prompt 覆盖**；字面量 `</content>` 必须转义。

*防什么*：prompt 注入逃逸。录制里如果出现字面的 `</content>` 字符串，LLM 会以为用户内容已经
结束，后面的话就成了指令。

### 7. CLI 的输出必须有界

给 AI 用的命令一律默认截断并标注 `truncated`。

*防什么*：一条录制塞满 agent 的上下文。单条录制可超 5MB（完整 system prompt + 71~100 个工具
的 JSON Schema），**一条就够**。

### 8. 配置体检只读

绝不写 settings.json 或凭据，不提供自动修复（与不变量 3 同源）。

*防什么*：自动修复反咬用户。配套三条：

- **宁可漏报不可误报**——规则分不清就闭嘴。误报第二次之后，横幅就再也没人看了。
- error 级可以拦启动，但**必须留 `force` 逃生门**——规则可能错，用户比规则更懂自己的环境。
- 从真实失败反向找样本，攒齐了再上规则，不凭想象写规则。

### 9. 显式还原动作的四条边界

「一键还原上游配置」（`upstream_history.restore`）是唯一被允许写多个字段的路径，四条边界一条不能少：

1. **只写 `ANTHROPIC_*` 前缀键**，文件其余部分（`OTEL_*` / `permissions` / `model` / 行尾符）一律不动。
2. **只能还原到本机采集过的历史快照**，不接受任意输入的 URL/token —— 不给自己开一个写凭据的任意入口。
3. **写前必备份**，走 `settings_guard` 的原子写。
4. **patch 态下拒绝执行**；自指地址不入历史、也不可还原。

*防什么*：这条不变量的存在本身是有代价的（它放宽了不变量 1），所以边界必须写死。特别是第 2 条——
一旦接受任意入参，这个端点就从"还原"变成"任意改写用户凭据"，而它是个无需认证的本机 HTTP 接口。

*为什么它不违反不变量 8*：体检的"自动修复"是**凭规则猜出一个值**写回去，猜错就反咬用户；
这里写回的是这台机器上**真实存在过**的那一组值，一个字节都不发明，且由用户显式选定目标。

### 10. 自更新只做用户点的那一步，且只认硬编码的那一个来源

「检查更新 → 下载 → 安装并重启」是本项目**唯一会下载并执行外部二进制**的路径，五条边界：

1. **来源硬编码**（`updater.REPO` / `API_LATEST`），不接受任何可配置的下载地址或"自定义更新源"。
   一旦可配置，这个**无需认证的本机 HTTP 接口**就成了"让本机下载并运行任意二进制"的入口。
   同理 `POST /api/update/open-releases` 无入参——否则它就是"用系统浏览器打开任意地址"。
2. **只走 https，且逐跳校验重定向目标的 host**。GitHub 的资产下载必然 302 到对象存储，
   只查第一跳等于没查。
3. **校验和有则必比，无则明说**：release 带 `SHA256SUMS.txt` 就强制比对，不符即删文件并报错；
   没有就在界面上写明"本次无校验和，仅传输层保护"并把实测值摆出来。**默默降级比不做更糟**
   （惯犯 ③ 的形状）。
4. **先落 `.part`，校验通过才改名**；开工前清空更新目录，失败绝不留下一个看起来完好、
   来路不明的 exe 躺在那里等人双击。
5. **绝不静默**：没有定时检查、没有后台安装，每一步都由用户点击触发；**录制中拒绝替换且
   不代劳停止代理**——停代理要写用户的 settings.json，那是有副作用的动作，不该由"我想升级"
   这个意图顺带触发（与不变量 8「不提供自动修复」同源）。

*防什么*：一条"看起来很方便"的自动化路径，把本工具变成本机上的下载执行器。而它替换的还是
自己——**出事时用户手上连一个能用的程序都没有**，所以就地替换必须可回滚（`swap_in_place`
三步：同目录中转 → 改名旧文件 → 换入新文件，任一步失败原样退回）。

> **自检**：新增任何会写 settings.json、渲染上游内容、或给 agent 输出的代码路径时，回来对一遍
> 这十条。加了新的不变量也写进这里——这是唯一的清单。

## 二、惯犯 bug（改代码时对照）

这些在项目里**重复出现过**，不是一次性的。它们是这个项目的结构性弱点，新增代码或字段时
按清单自检。（**标题不写条数**——它会长，写了就是下一处腐化，理由同 `doc_audit` 的对账清单。）

| 类型 | 病灶 | 第一次撞 | 同型再现 | 收口机制 |
|---|---|---|---|---|
| **① 死配置** | UI 给了承诺、代码零消费 | `retention_days` / `auto_start_proxy` / `redact_headers` 三个配置 UI 有开关、后端不读 | 体检模块主动交代 scope 边界（防同样的过度承诺） | 加新配置必须**前端 / `config.py._DEFAULTS` / 实际消费点**三处都接通，任一处断了就是新死配置 |
| **② 键名错位** | 生产方写 `input_tokens`、消费方读 `input`，中间没有任何东西会报错 | DAG 节点 token 恒为空 + CLI token 统计恒 0——归一化逻辑被抄了三份 | 索引加字段后读取只校验 off/len，旧索引静默缺字段 | 归一化收口到单一真源 `classifier.usage_norm`；索引字段集变化必须 bump `IDX_SCHEMA`，版本不符整体重建 |
| **③ 静默吞异常** | `except: pass` 掩盖数据丢失 | 录制落盘失败，LIVE 界面还在跳、盘上没字节 | 自测抢固定端口，Flask 在后台线程 bind 失败而主流程照常宣布「已起」；聚合卡三行内容塞进 62px 固定高，badges 行被 flex 压缩+overflow 裁到 10px——per-kind 计数徽章视觉消失而 DOM 里在（260803） | 异常要么打日志要么上抛，**不许裸 `pass`**；失败要计数（`_WRITE_ERRORS`）；固定高度的卡片验证「末行内容完整可见」，存在性检查不等于像素完整性 |
| **④ 测试数据不像真流量** | mock 形状错，自测一路绿灯，验证的是自己的幻觉 | 非流式响应丢 usage——而安全分类器调用恰恰是非流式 | `dev_seed` 造的样例没有计费头 / session 头 / reminder 包裹，身份与会话逻辑一条都测不到 | `dev_seed.py` 的形状照真流量复刻，改判别逻辑必须同步改样例 |
| **⑤ 以自身假设代替 harness 事实** | 「CC 大概是这样的吧」写进实现，而 CC 早就明说了 | 只实现 gzip/deflate，而 CC 每个请求都写着 `Accept-Encoding: gzip, deflate, br, zstd`——DeepSeek 选了 br，安全分类器响应整个丢空 | `_parse_sse` 不认 `error` 事件，而 CC 的 SDK 对它**抛异常**——于是失败被录成成功，失败聚合长期漏统计 | 动手前先去读 CC 说了什么（下一节三个权威来源）；实现范围对着 CC 的清单，不对着自己的印象 |
| **⑥ 前端引用解析不了（不是语法错）** | 名字写错了，但**没有任何东西会报错**——JS 里是运行到那一行才 ReferenceError，CSS 里是选择器合法却匹配不上 | 调 `loadStatus()` 而真名是 `refreshStatus()`：ReferenceError 把成功分支甩进 catch，表现为「修好了但绿色回执不出现」（260807） | 同一轮：提示元素写 `class="sub"`，而 `sub` 的规则是 `.srow .sub`、元素却是 `.scard` 直接子元素——字号没生效，是用户看出来的 | `tools/check_refs.py` 静态解析每个 JS 调用名与每个静态 HTML 类用法；**`node --check` 挡不住这一类**，它只验语法结构 |
| **⑦ 只修了撞见的那一层** | 同一个病有多层，修完撞见的那层就当治好了，**没问"还有没有别的层"** | 解码的**压缩层**：只实现 gzip/deflate，br 响应整个丢空。那次建立了 `decode_error` 留痕机制，还写下「格式必须支持 CC 声明的全部编码」（260731） | 解码的**字符层**：错误体无条件 `decode("utf-8", errors="replace")`，非 UTF-8 网关的错误消息**落盘即变 `�`**、有损不可逆——`decode_error` 那套机制整条思路停在压缩层，字符层一个字没提（260807 运行分析查出） | 解码固定是两层（content-**encoding** 压缩 / **charset** 字符），两层各自留痕（`decode_error` / `charset_fallback`）；更一般地：**修一层时把"这个病还有哪些层"写进注释**，并检查上一轮建立的留痕机制是否覆盖新层 |

**②④⑤都已经复现过第二次**，说明它们不会自己消失。⑤ 是 260731 两次事故后新增的，
两次的形状一模一样：**CC 白纸黑字声明的东西，我们没去读。**⑥ 是 260808 新增的，它同一轮
就出了两个实例——**共同点是「错了但全链路静默」：编译不报、自测不报、界面不报，只有人真去点/看**。

⑦ 也是 260808 新增，但它和 ③ 的关系值得说清：**③ 是"丢了数据不吭声"，⑦ 是"以为已经治好了"**。
字符层那次尤其刺眼——上一轮（brotli）刚为同一个病建了留痕机制、还留下一句「格式必须支持
CC 声明的全部编码」，**那句话本身就把视野锁在了压缩格式上**。收口机制写得越具体，越要小心
它顺手划定的边界：`_decode_body` 的名字叫「解码正文」，实际只管压缩，一年没人觉得不对。

第四条值得单独说一句，因为它的适用范围比测试数据大得多：

> **测试数据必须长得像真流量，否则它就是在验证自己的幻觉。**

这句话同样适用于一切「看起来合理但没被真数据验证过」的设计假设。260725 那批 15 条真录制一次
推翻了三个看起来完全合理的子代理判别假设（见下一节）——那就是这种怀疑的兑现。

## 二·五、harness 事实的三个权威来源（加解析逻辑前先读这节）

这个工具录的是 **CC 的流量**，所以"要支持什么"这个问题**从来不该由我们猜**——CC 自己一直在说。
惯犯 ⑤ 的两次事故都是没去读它说的话。下面三个来源按可信度排序，加任何解析逻辑前先过一遍。

> 📖 **本节是 CC 的具体事实。** 泛化到任何 harness 的做法（三类来源怎么迁移、C 类取不到时
> 怎么办、盘点产出什么）见 [同类工具构建手册.md](../methodology/同类工具构建手册.md) 的 **单元 0：harness 观测面盘点**
> ——**接 codex / opencode 等新框架时读那篇，不是这篇。** 两边不重复内容：那边讲方法怎么搬，
> 这边只列 CC 的清单与判据。

| # | 来源 | 它回答什么 | 怎么取 |
|---|---|---|---|
| **S1** | **CC 的请求头** | CC 声明自己接受什么、启用了哪些扩展 | 扫真录制的 `request.headers_safe` 全集 |
| **S2** | **CC 的请求体字段** | CC 实际在用协议的哪些特性 | 扫 `request.body` 顶层键全集 |
| **S3** | **CC 源码的响应处理分支** | CC 能消费什么形态的响应＝我们必须能录什么 | 反编译 bundle，看 SSE 累积器的 `switch` |

**S3 是最有力的一条**：CC 的 SSE 累积器里有几个 `case`，就是响应形态的完整清单——我们少一个，
那种响应就在录制里凭空消失。（⚠️ 反编译产物里同名 `case` 可能属于 React 渲染层而非 wire 层，
必须逐条看上下文，只 grep case 名会误报。）

两条已经兑现的判据，可直接照用：

- **`Accept-Encoding` 就是必须支持的解压格式清单**（当前 `gzip, deflate, br, zstd`）。
- **`anthropic-beta` 就是 CC 启用了哪些协议扩展的清单**（实测 19 个特性、随版本漂移，
  含一对改名：`server-side-fallback-2026-06-01` → `fallback-credit-2026-06-01`，基线两个都收）。
  出现没见过的特性，就该去查它带来什么新字段、新块——**它是发现下一个盲区的雷达**。
  ⚠️ 「实测全集」是**出现过的全量的并集**，不等于白名单。基线的单一真源是
  `classifier.KNOWN_BETAS`，前端由 `render_template(known_betas=…)` 注入消费——
  **只在 classifier 里改**（260802 从 index.html 上提：清单原先只在前端，而唯一会问
  "有没有新 beta"的消费者是走 `/api/unknowns` 的 AI，它拿不到）。

**雷达已落地**（260802）：`/api/unknowns` 不只盯 beta，还盯响应块类型/字段、请求体字段、
stop_reason、thinking.type——凡是命中 `classifier.KNOWN_*` 集合外的值就报，每项带 `snippet`（值
片段）+ `hosts`/`cc_versions`（归属）+ `betas`（特异关联）+ `samples` id。

**KNOWN 维护循环**：雷达发现 → **先看 `hosts` 判来源** → 确认是 Anthropic 标准字段 → 并入
`KNOWN_*` + bump `IDX_SCHEMA` → 雷达清空这项 → 只剩真未知（首跑 6 类盲区审查后
with_unknowns 259→1）。

> ⚠️ **循环里最容易走错的一步是"确认"那一步**（260802 复查实证）：那天全部 5 条未知的 host
> 都是同一个第三方网关（OpenAI 风格的 `tool_result` 响应块），而端点当时只说"协议演进"。
> 照着提示把它并进 `KNOWN_*`，等于**用第三方网关的形状去放宽官方链路的判据**——将来官方真
> 出现同名异构块，雷达反而哑掉。所以：**并入 `KNOWN_*` 的前提是它在官方 host 上也出现过**，
> 单一第三方 host 独占的形状差异应该记进同类工具构建手册，不是并进已知集合。

三条设计约束，改雷达时别破：

| 约束 | 为什么 |
|---|---|
| 已知集合**硬编码 + 版本号**，不动态算频次 | "已知"必须确定可审计，不能随数据漂移 |
| 本工具自己的降级标记（`CAPTURE_ARTIFACT_KEYS`）单列 `degraded` | 混进协议未知会双向坏事：真信号被自己的噪声顶掉（实测 07-29 全天 3 条未知全是它），录制降级又被埋在"协议演进"语境里没人管 |
| beta 关联算**提升度**不算裸计数 | 裸计数只会指向基线出现率最高的那几个（实测：报出来的 5 个 beta 恰好是当日出现率 100%/96% 的前 5 个）。要"来源"就得比基线 |

机制与迁移方法论见 `docs/methodology/同类工具构建手册.md` 单元 10。

### 官方标识符优先，启发式只作兜底（260801 对账定案）

归属/关联类推断的第一性问题永远是「**CC 是不是已经给了 ID**」，给了就用，启发式推断
（文本对齐、时序邻近、措辞指纹）只在 ID 缺位时兜底。CC 目前给的三个官方标识符：

| 标识符 | 位置 | 用途 | 注意 |
|---|---|---|---|
| `cc_is_subagent=true` | 请求体 system 计费头 | main/subagent **身份判别** | 260725 定案（见第四节） |
| `X-Claude-Code-Session-Id` | 请求头（**全部**请求，含 aux） | 主线泳道键 + **aux 精确挂接** | 子代理复用父的，只能分组不能判身份 |
| `X-Claude-Code-Agent-Id` | 请求头（仅子代理，07-31 起） | **子代理泳道键**（优先于 md5 对齐键） | = CC jsonl `subagents/agent-<id>.jsonl` 文件名，同一 ID 空间 |

两个教训摆在这：**不要放着上游明明白白给的字段不用，去猜**——aux 挂主线一直用「全局时序
最近的主线」推，直到对账才发现 aux 请求 100% 带 session 头（多会话日挂错 9/745）；
子代理实例分组曾用 `md5(派生者|prompt)`，而 CC 给的实例 ID 能直接 join 本地 jsonl。

**对账方法**（换新 harness / 新版本后重跑一次）：枚举真实录制的字段全集
（`tools/official_fields_probe.py` 扫 headers/body 键），再与被测工具的本地日志交叉核对
ID 空间（`tools/agent_id_probe.py` 把录制头值与 `~/.claude/projects/*/subagents/` 文件名
对上了 3/3）。凡「启发式推断 + 官方字段已存在」的地方，改成官方字段优先。

### 解析必须发生在录制之后，不能发生在录制之前

260731 同一天暴露了两次"数据不可逆丢失"，根子是同一个：

> 我们先解析、只存解析结果。于是**解析器的认知边界就是录制的边界**——它没认出来的东西，
> 不是"以后再补"，是**当场永久丢失**。

- br 压缩：解压失败 → 正文没存 → 历史 security 响应回填不了。
- 流内 error：SSE 原文不留存 → 那 5 条可疑记录到底是不是 error 帧，事后查不了。

所以：**凡是"先解析、只存解析结果"的地方，都要问一句"解析失败/不认识时，原始证据还在吗"。**
至少要做到解析失败时如实落痕（`decode_error` 就是这么来的），不许静默留空（惯犯 ③）。
全量留存原始字节与体积治理的权衡属于路线图 0.5.x，别单独拍板。

### CC 安全分类器的运行机制（260731 逐条核对 wire 记录摸清）

写解析/分类逻辑时的默认前提，不用再重新推：

1. **审查时序**：模型在 assistant 响应里提出 `tool_use` → CC 逐个发 security 审查请求
   （`max_tokens=2112`、**非流式**）→ 审查通过才真正执行工具 → 执行完回传 `tool_result`。
   wire 上的判据：security 请求夹在 tool_use 所在请求之后、`tool_result` 回传之前；
   **放行的铁证是后续出现 `tool_result`**。
2. **fail-closed**：分类器不可用时 CC 直接不执行工具（提示 try this action again），
   读操作（Read/Grep/Glob）不受影响。拦截的特征 = 无 `tool_result` 回传 + 无工具副作用。
3. **压缩协商在 HTTP 层，Anthropic 协议不管**：`Accept-Encoding` ↔ `Content-Encoding` 是
   HTTP/1.1 标准，压缩策略完全由上游网关自选。**同一份代码在不同上游下表现不同，
   不代表缺陷与上游有关**——br 只有 DeepSeek 在用（实测 10 天：br 38 条全来自 DeepSeek，
   其余 1,172 条全是 gzip），但缺陷从 CC 的请求头就能判定。

## 二·五·五、存储分层：一天有两种形态（260825）

改任何读取录制的代码前先看这节。**别再自己拼 `captures/{date}.jsonl` 路径**——压实上线前
全仓有六处各自拼路径，压实之后它们会各自静默失效：文件不在了 → 当成空的一天 → 列表空白
但没有任何东西报错（惯犯 ③ 的形状）。读取一律经 `capture_store._Day` / `iter_records()` /
`list_dates()` / `get_capture()`。

### 为什么要压实（数字先于设计）

CC 因 prompt caching 每轮把整段历史原样重发，而 `append` 逐条全量落盘。本机实测：

| | 2026-08-11（49.3MB） | 2026-08-09（477MB） |
|---|---|---|
| `messages` 占比 / 其中唯一内容 | 60.8% / 8.4% | **75.4% / 6.6%** |
| `tools` 占比 / 其中唯一内容 | 23.4% / 1.8% | 17.8% / **0.2%** |
| 响应侧全部 | 2.2% | 0.9% |

**不是"压缩率不够"，是"同一份东西存了几十上百遍"。** 旧的 zip 归档用 DEFLATE，滑动窗口
32KB，而重复块相隔几 MB 到几十 MB——它在原理上就看不见跨记录的重复（实测只有 2.6x）。
换成内容寻址去重后：500MB 的一天 → 14.8MB（33.9x），单条随机读中位 17ms / p90 27ms。

### 三个动作的语义边界（命名先划清，否则 UI 上会打架）

| 动作 | 语义 | 删东西吗 |
|---|---|---|
| `compact_date()` 压缩 | 原地压实成 `{date}.pack/`，读取侧透明 | ❌ 什么都不删，`uncompact` 可逆 |
| `archive_date()` 归档 | 打成可搬运的单文件 `.ccwa` | 默认不删；`keep=False` 才删（清理语义） |
| `enforce_retention()` | 按天数自动删 | ✅ **唯一会自动删数据的动作** |
| `snapshot_*` | 用户显式保存的拷贝 | ❌ 永不自动清理 |

`snapshot_store.py` 头部有一份同型的边界声明，**改这里必须同步改那里**（副本必然分叉）。

### 三条不许破的线

1. **今天永远不压。** `append` 只写今天；压实今天就要和写盘热路径抢同一个文件，而代理
   透明性是本项目第一优先级——录制体积再大，也不值得让"转发"这条路上多一个可能失败的环节。
   压实全程不进 `append` 的同步段，这一点是**由"只处理过去的天"从结构上保证的**，不是靠加锁。
2. **校验通过才删原文件，而且是逐字节全量比对**（`pack.verify_against`）。抽样过了不等于
   没坏，而这里坏一次的后果是原始证据被删掉且无人察觉——本项目最不能容忍的失败形状。
   实测 14 天全部采样记录满足 `json.dumps(json.loads(line), ensure_ascii=False)+"\n" == line`，
   所以还原能做到逐字节；但"实测成立"不等于"永远成立"，所以每次压实都真的比一遍。
3. **`PACK_SCHEMA` 不符 → 拒绝读并报错**，不许按旧字段猜着读。这是 `IDX_SCHEMA` 那个
   「字段集变了、旧数据仍结构有效、逻辑静默退化、没有任何东西会报错」的同型坑；而且更严
   一档——索引是缓存可以重建，pack 是**事实源**，读不懂就必须报错而不是给出半份数据。

### 格式要点（细节见 `src/pack.py` 的模块 docstring）

- blob 引用用**整数下标**不用哈希串：截断哈希可能撞（撞了就是把 A 对话的内容显示成 B 的，
  这种错没有任何东西会报错），写全 32 个 hex 又要多占 4MB 骨架。写时用完整 128 位 blake2b
  去重，落盘只留下标——哈希只活在打包过程的内存里，不进格式。
- blob 池**按天独立**：跨天共享能省的主要是 tools/system，而它们在一天内已被压到 0.2%~1.0%，
  增量收益很小，换来的却是引用计数。按天独立 = 删一天就是删一个目录，不会出现"删了昨天
  导致前天打不开"这类只在删除时才暴露的耦合故障。
- 压实态的**索引整体压缩**（`idx.jsonl.zst`）：一切缩小 30 倍之后索引反成了大头
  （477MB 的一天里索引 7.6MB，因为每条索引都带一份 `sys_head`）。压实态的一天是冻结的，
  没有追加语义，所以可以整体存成一个 zstd 帧——反正读取侧本来就是全读进内存的。
- 索引 `off/len` 指向**锚点文件**：jsonl 形态是主文件，pack 形态是 `skel.jsonl`。
  `/api/dag` 的缓存键也必须用锚点大小，写死 `.jsonl` 会在压实后恒为 0 → 缓存永不失效。

### 外来录制：`sources/<标签>/`

两台机器同一天都在录，日期一定撞车，所以导入的录制进独立命名空间。混进 `captures/` 的
后果不是报错，而是更糟的东西——**把别的机器的证据当本机事实读，排查会直接跑偏**。
因此还有一条界面不变量：**导入的录制必须一眼可辨**（捕获页顶部的来源切换条 + 实心点标记）。

## 二·六、识别体系的七层地图（加分类逻辑前先在这找位置）

「这条请求是什么类型、这轮谁发起的、这个子代理是谁派生的、这次辅助归哪条主线」——这些判断在
`classifier.py` 里散成十几个函数，但它们**不是十几套判据，是七层叠起来的一套**。加新分类逻辑
前先在这张表上找到它属于哪一层，再按上一节「官方标识符优先」决定用权威位还是启发式。

| 层 | 判什么 | 权威信号（优先） | 启发式兜底 | 产出 |
|---|---|---|---|---|
| **L0** 原始留存 | *（不是分类，是底座）* | 录全量原始字节 | — | 一切下游判断的证据（见本节前一小节「解析在录制之后」） |
| **L1** 请求 kind | 这是什么**类型**的调用 | `path=count_tokens`；计费头 `cc_is_subagent` | system 措辞指纹（title/security/compact/main）；结构兜底（有 tools+system → main） | `kind` |
| **L2** 轮起源 | 这轮**谁发起**的 | `cc_entrypoint`（**只覆盖 sdk 起源**，其余仍无官方位） | 轮首文本前缀白名单 `TURN_ORIGIN_SYNTHETIC` / `_COMMAND` | `origin`（user/synthetic/command/sdk/partial） |
| **L3** 泳道 | 属哪条**会话线** | `X-Claude-Code-Session-Id`；`X-Claude-Code-Agent-Id` | `md5(首条 user\|uid)`；agent 指纹 | `lane_id` |
| **L4** 子代理父子 | **谁派生**了谁 | `cc_is_subagent`（身份）+ `agent_id`（实例） | Task/Agent prompt 子串对齐（**先剥 `<system-reminder>`**） | trigger 边 + 实例泳道 |
| **L5** aux 挂接 | 这次辅助**归哪条**主线 | `session_id` 精确匹配 | 全局时序邻近 | near 边 |
| **L6** 雷达（**给 AI**） | 有没有**不认识/可疑**的 | `KNOWN_*` 集合对照 | — | `/api/unknowns` |

读法：**L1–L5 是确定性的运行时分类**，每层两档——官方标识符优先、启发式只作兜底；**L6 不是
分类器，是给 AI 的发现雷达**（离线/分析时用，不参与运行时判断）。

### L2 是七层里官方标识符最薄的一层

这是「CC 自己合成的伪轮被画成主线」这类问题的**根因**，而不是分类器写坏了：

> 其余六层 wire 上都有 CC 明明白白给的字段（L1 计费头与 path、L3/L4 session/agent id、
> L5 session、L6 已知集合），**L2 只有一个 `cc_entrypoint` 能认出"程序驱动"，剩下的全靠
> 措辞启发式**——CC 改一句提示词就能让它失效。

CC 会自己合成伪 user 消息触发一整轮（建议补全 / 离开回顾 / 内部检索派发 / 后台任务通知），
它们与真人消息在 wire 层的结构判据上**完全重叠**（`tools_n` / `max_tokens` / 计费头版本哈希
实测无一能分），稳定的只有措辞。所以 `TURN_ORIGIN_SYNTHETIC` / `_COMMAND` 是白名单前缀，
不是真值。**只有 `sdk` 那一档是官方位**（260810 补：`cc_entrypoint` 以 `sdk` 开头 = 程序驱动的
会话）——它是拿 jsonl 对账时捡回来的，见下。

**fail-safe 方向不许反过来**：命中不了的新形态一律落回 `user`——宁可把伪轮当真轮，不能把真人
消息弱化。伪轮显示成 main 只是不好看；把真人回合降档，是这个工具最不该犯的错。同理，伪轮
**只降档不隐藏**：它们带着真实流量和真实 token 成本，藏起来就是惯犯 ③（静默丢数据）。

### CC 本地 jsonl 是第四个权威来源 S4，但**只在开发期用**

上一节的三源 doctrine（S1 头 / S2 体 / S3 源码分支）之外还有一个：**CC 事后写进本地 jsonl 的
对话记录**，即「CC 自己认为哪些是真实对话事件」。它带着 L2 缺的那个位——每条 user 消息的
`promptSource`：`typed`/`queued`/`suggestion_accepted` 是真人，`system`/`sdk` 是机器。但它
**不过 wire**，只躺在 `~/.claude/projects/`。

> 🔒 **边界（260810 拍板，别越）**：读本地 jsonl 是**开发期能力，不是运行时能力**。
> 产物只碰 `settings.json` 一个字段、数据面只有自己录的流量——这是这个工具全部克制姿态的
> 地基，不能为了一个分类器精度顺手放宽。对账脚本放 `tools/`（不在 `build.spec` 的 `datas`
> 里），**隔离由打包边界保证，不靠一个可关闭的开关**（开关会被误开、要维护、要写文档解释）。
> 运行时要不要用 jsonl 是另一个问题，尚未决定，也不预留半成品。

**对账工具**：`tools/origin_probe.py`（与 `lane_probe.py` 同族）。两条 join 链路都锚在双方
各自的官方 id 上：

| | 链路 | 适用 |
|---|---|---|
| **T1** | wire 响应头 `request-id` → jsonl `requestId` → 沿 `parentUuid` 上溯到轮首 → `promptSource` | 只有官方上游回 `request-id`（实测第三方网关基本不回） |
| **T2** | wire `X-Claude-Code-Session-Id` → jsonl 同 `sessionId` 的轮首集合 → 轮首文本前缀匹配 | 覆盖第三方网关；最后一公里是文本匹配，证据强度低于 T1 |

**260810 首次全量对账结果**（8 天真录制，2,339 个判得动的主线轮）：

| 指标 | 数 |
|---|---|
| 启发式与 jsonl 真值一致 | **99.8%** |
| **把真人轮误判成 synthetic（危险方向）** | **0 例** ← 这一格必须永远是 0 |
| 白名单漏掉的伪轮（判 user、真值是机器） | 4 例，**全部是 `entrypoint=sdk-cli`**，已由新增的 `sdk` 档接住 |
| 轮首成功的主线轮里，CC 自说自话的占比 | **45%**（`user` 只占 50.3%） |

两条要记住的：

1. **雷达的第一个真实产出不是"新增一条措辞前缀"，是"发现有个官方字段一直没用"。** 那 4 条
   漏网轮在 wire 侧根本没有共同措辞（脚本想发什么发什么），共同点是 `cc_entrypoint=sdk-cli`，
   4/4 命中且 2,180 条 `cli` 真人轮零误伤。这正是 §二·五 那条教训的复现：**别放着上游明明
   白白给的字段不用去猜。**
2. **统计伪轮占比的分母要剔掉失败轮。** 上游 504/429 时 CC 会把同一句话重发几百次，每次都是
   一个 `turn_start`——实测某天 2,049 个"轮"里 2,000 个轮首是 504，真实话题只有三个。不剔
   就是拿重试次数稀释占比。

新 synthetic 类型的白名单维护，**原样复用上一节的 `KNOWN_*` 循环**：雷达发现 → 先看 hosts 判
来源 → 判定稳定指纹是哪句开头 → 并入 `TURN_ORIGIN_SYNTHETIC` → 雷达清空这项。CC 每演进出
一种新后台任务，走一遍这个循环，而不是回头改结构判据。（`origin` 在 `build_dag` 里现算、
不落索引，所以只改前缀清单**不需要** bump `IDX_SCHEMA`；动到索引字段才需要。）

三条别破的约束：

| 约束 | 为什么 |
|---|---|
| jsonl 对账**不进运行时分类器** | L1–L5 保持纯 wire、快、独立可用；jsonl 不在场时工具照常工作 |
| jsonl 缺失**绝不降级真人回合** | join 有损时，误降真人回合比「伪轮显示成 main」严重得多 |
| 「jsonl 里没有」**不等于**「机器发起」 | 还有两种成因：请求失败（429/5xx，CC 没等到响应自然没写）、轮被打断。混进雷达就是纯噪声——探针按 wire 侧自己的 status/errors 先摘掉它们 |

## 三、防御性设计：每个机制防的那件事

项目里「防自己未来某天手贱」的机制，每条配一句它防什么。改代码时如果准备绕过其中任何一条，
先读这一列。

| 机制 | 防什么 |
|------|--------|
| `IDX_SCHEMA` 版本号 | 加字段后旧索引静默缺字段、判别逻辑退化无报错 |
| `usage_norm` 单一真源 | 归一化逻辑被各处各抄一份（这个错犯过两次） |
| 体检只读 + force 逃生门 | 自动修复反咬用户 + 规则绝对化锁死用户 |
| marker 比对当前值 | 陈旧 marker 覆盖用户新配置 |
| AI 解读定界符硬编码 | prompt 注入逃逸 |
| 自测双环境变量覆盖 | 动真用户配置（等于拿用户的 CC 当小白鼠）|
| 自测挑空闲端口 | 写死端口被占时污染别人的实例 |
| `dev_seed` 照真流量复刻 | 测试数据验证自己的幻觉 |
| `_WRITE_ERRORS` 落盘失败计数 | 静默吞异常（界面在跳、盘上没字节）|
| snapshot 自指守卫 + forward 兜底 | snapshot 守卫被绕过或 `_original_base_url` 被污染时仍不递归 |
| headers 脱敏恒开（无开关）| UI 给开关等于提供了「把 API key 明文写进 jsonl」这个选项 |
| 原子写保行尾风格 | Windows text mode 把 LF 转 CRLF 污染 git diff |
| 外部变更检测不用 mtime 基线 | patch 完成 → 监视器首轮之间的竞态窗（e2e 实测踩中）|

有一条不变量因此升级成了通用规则，写在这里因为它最容易漏：

> **凡是从外部（文件 / marker）读来一个 URL，准备当成 original 记下、或写回 settings.json 的
> 入口，都必须过本地地址守卫。**

漏掉任何一个入口的后果是：代理把请求转发给「上游」，而它认定的上游就是自己 → 无限递归 →
CC 全部请求超时，而且这个污染会写进 marker **跨重启传播**，自愈机制反而给它续命。

## 四、子代理判别定案（实测确立，别再重复推翻）

另有四条**静态对账**（不是自测，但改对应面时要跑）：

```bash
uv run python tools/check_i18n_js.py    # 改 index.html 后：三语键集同步 + <script> 语法
uv run python tools/doc_audit.py        # 改端点/CLI/IDX_SCHEMA/语义 token 后：代码事实 vs 文档说法
uv run python tools/check_render.py     # 改 DAG 卡片/高度常量后：固定高度卡内容不被 overflow 裁（v0.4.8 同型防线）
uv run python tools/check_refs.py       # 改 index.html 后：JS 调用与 CSS 类引用能否解析（260807 两个真 bug 的防线）
```

**前端的三条各守一个形状，别指望其中一条兜住另外两条**：`check_i18n_js` 守语法与三语键集、
`check_render` 守固定高度卡的裁切、`check_refs` 守「引用能否解析」。260807 上游历史那一轮
撞出的三个前端 bug 恰好各占一个形状，而当时只有第一条存在——另外两个都是**人真去点/看**
才发现的（调 `loadStatus()` 而真名是 `refreshStatus()`，表现为"修好了但绿色回执不出现"；
`class="sub"` 挂在 `.scard` 下而规则是 `.srow .sub`，表现为字号不协调）。两者**都不是语法错**，
`node --check` 只验语法结构不验标识符能否解析，CSS 里一条匹配不上的选择器在浏览器看来完全合法。

`check_refs` 的两条判据都以**当前基线 0 误报**为验收线（达不到就调判据或降级成提示，
不允许"先报着以后再说"——理由与配置体检的铁律同源：第二次误报之后就再没人看了）。
它的 `--self-test` 用内存变异复刻那两个真 bug 验证检查真会响。

`doc_audit` 对账一批机器可判定的东西（端点是否进了 `API契约.md`、CLI 子命令是否有文档、
文档指向的文件是否存在、`IDX_SCHEMA` 数值、自测清单里的文件是否存在、有没有引用已删端点、
以及**界面语义 token 三套外观是否都给了取值**）。它是 `docs/文档维护策略.md` 策略五挂了很久
的"待实现"，260802 补上：那份策略自己的判据就是「给腐化开的药方如果需要人工定期同步，
它自己就是下一处腐化」。

**260808 起它是闸门，不再是报告**：有硬差异就退出 1，CI 在 PyInstaller 之前跑它。
之前它退出码永远 0，理由是"差异不等于错误、判断留给人"——那个理由只对一半差异成立：

| | 例子 | 处置 |
|---|---|---|
| **硬**：文档**说错**了 | 幽灵端点、断链、过期的 `IDX_SCHEMA`、不存在的自测文件、缺取值的 token | **挡发版**。读者照着做会直接撞墙 |
| **软**：文档**没说** | 未登记的内部端点 / 子命令、死 token | 只提示。读者顶多查不到，不会被骗 |

不分类就一律挡的话，第一个有意不公开的内部端点会卡住发版，接着有人在 CI 里加 `|| true`，
**闸门就永久失效了——那比没有闸门更糟，因为它还挂在那里冒充防线**。

`uv run python tools/doc_audit.py --self-test` 验证两件事：给 token 检查造一个反例（删掉
classic 的一个 token）确认它真会报；再对每一类差异断言它落在硬/软的哪一边（含反向断言：
软差异**不该**挡）。**检查本身不被验证，就是下一个「守卫函数存在但调用点缺失」**——
而分类错了的闸门会一边放行一边打印「对账通过」，正是惯犯 ③ 静默失效的形状。

### 自测不抢固定端口

自测从 5150 起挑空闲口 + 用 `/api/proxy/status` 探活断言，**daemon 或 dev server 开着也能跑**。

此前写死 5051：被占时 Flask 在后台线程 bind 失败，而主流程照常宣布「已起」，请求打到别人的
实例 → 401 报错指向「转发坏了」这个完全错误的方向，还往对方的录制里掺假请求。**别再写死端口。**

### 前端改动：改完模板必须重启 dev server

`app.run(debug=False)` 下 Jinja **不自动重载**，模板渲染过一次就被缓存。改了 `index.html`
刷新浏览器看到的仍是旧页面。

判断方法：

```bash
curl -s http://127.0.0.1:5051/ | grep '<你刚加的注释>'
```

搜不到就是缓存，重启 dev server。（260729 实测踩到：原以为「dev server 实时读模板」，对着
旧页面查了半天改动为何不生效。）

### 测危险路径不许动真配置

`config.py` 认两个环境变量覆盖：

| 变量 | 覆盖什么 |
|---|---|
| `CCWA_HOME` | 数据目录（录制 / 索引 / 配置 / 日志）|
| `CCWA_CLAUDE_SETTINGS` | 上游 settings.json 路径 |

**自测一律走临时目录**。要采集真实流量做验证时，也用这两个变量隔离 + `--settings` 参数让被测
CC 走代理，工具读写全是副本：被测 CC 用真配置（真提示词、真模型、真凭据），只有 `ANTHROPIC_BASE_URL`
被 `--settings` 盖掉。

```bash
export CCWA_HOME='<临时目录>'
export CCWA_CLAUDE_SETTINGS="$CCWA_HOME/settings.json"          # 副本，patch 只会落到它
cp ~/.claude/settings.json "$CCWA_CLAUDE_SETTINGS"
uv run python src/desktop.py serve
claude -p "<任务>" --settings '{"env":{"ANTHROPIC_BASE_URL":"http://127.0.0.1:<port>"}}'
```

⚠️ **进程级 `ANTHROPIC_BASE_URL=… claude -p` 不生效**——CC 2.1.220 实测
无视它（死端口仍直连、录不到、无报错）；必须走 `--settings`（深度合并进真 settings，只盖
BASE_URL，保留凭据/模型）。

⚠️ **只隔离 `CCWA_HOME` 不够**：patch 的目标由 `CCWA_CLAUDE_SETTINGS` 单独决定，不设它就指向
你真实的 `~/.claude/settings.json`。260802 有人只设了前者去跑本项目的一个前端副本，于是两个
实例抢同一个 patch，正在用的 CC 被指到死端口断网。**两个变量是一对，不是二选一。**

注意被测 CC 的 `ANTHROPIC_BASE_URL` 要对上 daemon **实际监听**的端口（`find_free_port` 从 5051
起挑，被占就顺延），读 `$CCWA_HOME/port.txt` 或 daemon 启动输出确认——别照抄 5051。

⚠️ **`--self-test` 里重定向自己的文件还不够，被调用模块的模块级路径也要一起重定向。**
260807 `upstream_history.self_test()` 只把自己的 `HISTORY_FILE` 指到临时目录，而它调的
`settings_guard.backup_file()` 用的是 **settings_guard 的模块级 `BACKUP_DIR`** ——于是三份临时
假配置（带假 token）被写进了用户真实的 `~/.cc-wire-analyzer/backups/`，还占掉 `MAX_BACKUPS=5`
的名额，差一点把真备份挤出窗口。写新 self-test 时，把**整条调用链上所有模块级路径常量**
（`BACKUP_DIR` / `_PATCHED_MARKER` / `HISTORY_FILE` / `CONFIG_DIR` …）列一遍，逐个重定向 +
在 `finally` 里还原。环境变量隔离（上面那两个）只在**子进程**里有效，同进程内 import 完才改
模块常量的写法必须自己收尾。

⚠️ **`CFG.setup_logging()` 之后，未捕获异常不再打 stderr。** 它装的 excepthook 只写 `run.log`。
自测入口若照抄 `settings_guard.py` 的 `__main__`（先 `setup_logging()` 再直接调 `self_test()`），
断言失败时终端**一片空白只留 exit=1**，得去翻日志才知道断在哪——对自测来说这就是惯犯 ③
「静默吞异常」。新自测的 `__main__` 一律 `try/except` + `traceback.print_exc()`。

## 六、前端约定

- **无构建链**：`src/templates/index.html` 自包含（HTML + CSS + 原生 JS，无框架、无打包器）。
  这是刻意的——桌面 app 的前端加一条构建链，就等于给每个贡献者加一个 Node 工具链。
- **三语必须同步**：改任何用户可见字符串都要更新 `zh` / `en` / `ja` 三张 i18n 表。三张表的
  **键集必须完全一致**，缺键会在运行时显示成 key 名。改完数一下键数。
- **字体不可替换**：Inter / JetBrains Mono / Noto Sans SC（均 SIL OFL），打包进产物保证跨平台
  视觉一致。不要换成不可再分发的字体。
- **复制链路要自己接**：WebView2 把原生右键菜单绑在 debug 开关上、macOS WebKit 干脆没有 Edit
  菜单，所以复制全靠前端自绘右键菜单兜底。链路有三环：**能选中 → 右键有菜单 → 拷得到全文**。
  - 第一环是 CSS。**260801 起是黑名单**：`body` 默认 `user-select:text`，只给真正的交互控件
    （按钮 / 标签页 / 日期 chip / toggle / DAG 节点与泳道头）显式 `none`。此前是白名单
    （只有列出的类可选），意图相同但实现相反，于是每加一个展示组件就漏一个——`.crumb-id`
    （详情页 `req_xxxxxx`）、设置页 `.val`、关于卡片 `.v` 全漏了，用户报「很多界面拷不了字」。
    **默认值必须是能复制**：这软件里绝大多数文本就是给人拿走的，漏标注的代价应是「多一处能选中」。
  - 第二环是 `blockTextOf()` 的块选择器。不在选择器里 → `sel` 与 `blk` 双空 → `ctxInit` 直接
    不劫持右键 → **右键什么都不弹**。新增展示区块要么带 `.excerpt`，要么进这个选择器。
  - 第三环是「拷全文而非可见片段」（`.excerpt` 走 `_excerptRaw`，折叠态也拷全）。
- **三套外观是语义 token 的三份取值，不是三份样式表**（v0.4.7）。`:root` 拆成两块——
  **主题无关 token**（字体 / 圆角 / 过渡，三套共用）与 **深色取值**（默认外观）——再加
  `html[data-theme="classic"]`（经典暖灰，v0.4.6 原样）与 `html[data-theme="light"]`
  （实验室日光）。组件只引用变量，**不许在组件里写死颜色**。
  - 新增颜色先问「这是哪个语义」——找得到现成变量就用它（**每族什么时候用哪个，见
    [界面导览.md](界面导览.md) 第三层「语义 token 速查」**），找不到才三套一起加。
  - **拆两块是为了让这条可被机器查**：`tools/doc_audit.py` 检查深色块里的每个 token
    在 classic/light 是否都有取值，顺带报出无人引用的死 token（首跑清掉 7 个）。
    漏一个不会报错也不会白屏——那套外观只是静默落回深色的颜色，某个组件在纸面上变成深色块。
    **这就是它必须是检查而不是约定的原因**：约定靠人记，而这件事没有任何运行时反馈来提醒人。
  - **外观只属于 UI**：写 cookie + localStorage，`<head>` 里在首屏绘制前读回（避免深浅闪切），
    **绝不写进后端 `config.json`**——那份配置是代理行为的真源，外观进去就是把两件事绑死。
  - 泳道色板按外观分三份（`LANE_PALETTES`）：深色底用提亮版、浅色底用加深版。
    同一组色值不可能同时落在 `#131318` 和纸面上还都过 AA。
- **文字颜色必须过 WCAG AA（小字 4.5:1），且三套外观各自的卡面与软底都要算**（260801 定，
  v0.4.7 扩到三套）。`:root` 与两个 `data-theme` 块的注释里写了实测值——**改这些变量前先跑
  一遍对比度计算**。软底那一列比卡面低约 0.5，只按卡面调会漏。这条不是洁癖：原来的
  `--apple-secondary`(3.00) 与 `--text-faint`(2.37) 用在 `.cap-time`(11px) / `.cap-ttft`(10.5px) /
  `.thinking-text`(11.5px 斜体) 这些满屏都是的地方，用户直接报"字虚"。
  **算色的对象包括 JS 拼出来的内联色**：轮卡上的子代理徽章曾写死 `color:#fff` 落在
  "派生方色兑 45% 白" 的浅底上，实测 1.6:1——改成按亮度选前景（`fgOnHex`）后三套外观 7.5~11.5:1。
  写死的前景色只要背景是算出来的，就迟早对不上。
- **缩放用 `zoom`，不要用 `transform: scale()`**。后者是位图缩放，会真的把字变虚——而缩放这个
  功能本来就是为了治"字小且虚"，用 transform 等于把病治成原样。`zoom` 参与布局，字形按新字号
  重新光栅化。根元素的 `zoom` 与 DAG 内层的 `zoom` 相乘，DAG 的 fit 计算读 CSS px 不受影响
  （实测 100% 下 fit=0.810、125% 下 fit=0.634，图仍恰好铺满可视宽度）。
- **新加的用户可见状态别只在"某个函数里"渲染**：`setLang` 必须把所有 JS 拼出来的面板一起重渲
  （体检抽屉、失败聚合），`applyI18n` 只管带 `data-i18n` 的静态节点。漏一个就是"界面已切英文、
  抽屉里还是中文"。

> **自检**：改前端展示组件、用户可见字符串、字体或颜色时回看这里——三语键集是否一致 / 字体是否可再分发 / 新组件是否接了复制入口 / 新颜色是否过 AA / 切语言是否重渲，五件套缺一就是新坑。

## 七、模块依赖与两种运行模式

### 单 exe，三种调用

`desktop.py` 检测 argv：

- 无参数 / 双击 → **GUI**（pywebview 窗口）
- `serve` 子命令 → **headless**（Flask + 自动 patch 代理，不开窗，给 AI agent 用）
- `--help` / `-h` / `--ai-guide` 等 → **打印说明并退出**（不开窗、不弹模态框；正文与
  `/api/ai-guide` 同一份，见下）

为什么主通道是 HTTP 而不是一整套 CLI 子命令：`app.py` 早就有完整的 HTTP API，结构化 JSON、
不用 shell 转义、GUI 与 agent 共用同一份实现。macOS 同理，单二进制。

> ⚠️ **别再引用「noconsole 没有 stdout」这条理由**（260801 实测纠正）。准确的事实是：
> noconsole 进程**不分配控制台**，双击运行时没有可写的 stdout；但由 shell 以**管道或重定向**
> 启动时 fd 1 是有效句柄，`os.write(1, …)` 照样能写。实测矩阵（打包 exe，`--help`）：
>
> | 调用方式 | 能否拿到输出 |
> |---|---|
> | bash `exe --help \| head` | ✅ |
> | PowerShell `exe --help \| Select-Object` | ✅ |
> | `cmd /c "exe --help > f"` | ✅ |
> | PowerShell `$o = & exe --help` | ❌（PowerShell 不等 GUI 子系统进程，与 stdout 无关）|
> | 双击（无控制台、无重定向）| ❌（此时靠落盘的 `<数据目录>/ai-guide.md`）|
>
> 这条不准确的理由让 `--help` 白空了三周：换一台机器的 AI 试 `--help`，得到的是**弹出一个
> GUI 窗口**。教训与惯犯 bug ③ 同源——**把"我以为的平台限制"当结论写进文档，没人再去实测**。

`cli.py` 作为开发工具保留在源码里（`uv run python src/cli.py`），**不打包**——这仍是有意的：
打包它等于维护第二套面向 agent 的接口，而 HTTP 那套已经够用。

## 八、改动流程：issue 先行

**任何改动都先写方案再动手，不区分大小。** 先写下「改什么、为什么、否决了什么」，再改代码。

这条纪律的收益不在改动当时，在三个月后回看时：代码只能告诉你现在是什么样，**写下来的方案
才能告诉你为什么不是别的样子**。项目里多次出现「重新提出一个当初已经否决过的方案」——每次
都是因为否决理由没被写下来。

配套两条：

- **带新功能或新字段的改动，必须同步文档**。改完照 [文档维护策略.md](../文档维护策略.md) 的
  「每加一个功能时跑一遍」清单过一遍——那份清单是文档动作的真源，这里不重复。
- **改完收口**：值得未来回看的方案留档并在 CHANGELOG 记一条；纯琐碎的直接删掉，不留噪音。

## 九、发布

打 `v*` tag → CI 双平台构建 → release。**发完把上一版正文搬进 history 文件**（见下「CHANGELOG 分两层」）。

`.github/workflows/release.yml` 用**单独的 release job**（`needs: build` → 下载所有 artifact →
一次性 attach）。不要改回「每个平台各自 attach」——并发写 release 会丢 asset，这个坑踩过。

**任何地方都不写死版本号**——README、`app.py`、`pyproject.toml` 一视同仁。版本的唯一真源是
git tag：CI 构建前从 tag 生成 `src/_version.py`（`app.py` 运行时读它，`release.yml` 的
`Inject version from tag` 步骤），exe 的 /api/about 因此永远与 tag 一致。手抄一份就必然分叉——
这条铁律是被反复踩出来的：先踩了 README（抄一次下一次发版就忘改，三份 README 停在旧版本），
又踩了 `app.py:VERSION`（v0.4.2 的 tag 已推、exe 却自报 v0.4.1，连 pyproject 都没跟着升）。
`pyproject.toml` 的 `version` 字段虽无人消费（`package = false` 不装成包），CI 也顺带同步它，
免得再有人困惑「改了 pyproject 为何 exe 没变」。

### 版本号要在程序外也看得见（260808）

同一个 `src/_version.py` 现在有**四个出口**，全部由 CI 从 tag 生成的那一份派生，没有第二处手写：

| 出口 | 谁来刻 | 用户在哪看到 |
|---|---|---|
| `/api/about`、`--help` | `app.py` 读 `_version` | 程序里、agent 调 API |
| Windows PE 版本资源 | `build.spec` → `tools/version_res.py` | 右键属性 → 详细信息 |
| macOS `Info.plist` | `build-mac.spec` → 同一个模块 | 访达「显示简介」 |
| release 资产文件名 | `release.yml` 的 `APP_VERSION` | 下载目录里、Release 页 |

**两份 spec 共用 `tools/version_res.py`，不各写一份**——它们因"两份要同时改"分叉过一次
（mac spec 没跟上 `brotli`）。共享模块让分叉在结构上不可能发生，比事后加检查更彻底；
`doc_audit` 另有一条兜底，两份 spec 谁掉了这个 import 就挡发版。

资产名带版本（`cc-wire-analyzer-v0.4.11-windows.exe`）不是装饰：**属性页要点三下，
文件名是零成本**，而软件内的自动更新按模式匹配资产（`*windows.exe` / `*macos.zip`），
不认死文件名——改名字不会打断更新链路。release job 另出 `SHA256SUMS.txt`，
自更新据此校验（见不变量 10 第 3 条）。

### CHANGELOG 分两层（v0.4.7 起）

一个文件同时服务两个方向相反的读者就一定会撑爆：**顶部速览每次接手都要读、必须短；下方流水
要完整**。v0.4.7 那一刻 `CHANGELOG.md` 已是 1472 行 / 124K，速览沉在里面，本地开发每次读它
都要把整部历史一起读进来。于是拆成两层：

| 文件 | 装什么 | 谁读 |
|---|---|---|
| `CHANGELOG.md` / `.zh.md` | 速览 + 未发布 + **当前版本** | 本地开发 / AI 接手；**也是 CI 抽 release notes 的真源** |
| `CHANGELOG-history.md` / `.zh.md` | 已发版的完整正文 | 想翻旧账的人（GitHub Release 页有同一份） |

**发版顺序不能反**：先确认当前版本正文在 `CHANGELOG.md` 里 → 打 tag（CI 从它抽 release notes）
→ **再**把上一版正文剪进 history。反过来做，release notes 会空成 tag message 兜底。
这一步是「搬家」不是「同步」——两边没有副本，因此没有漂移风险。

**条目怎么写**：一句说改了什么，一句说为什么要紧；**实测数字留着**（它们是这些条目的全部价值——
"19 列 192 节点 → 18 列 68 卡"、"1.6:1"、"5414 条里 464 条从没解析"）。过程叙事、否决过的方案、
实现细节交给 `issues/closed/` 与 git——那是它们的归属，写进 CHANGELOG 只会让下一个人多读五分钟
才找到自己要的那一行。v0.4.7 首次按此重写：中文一节 189 行 → 35 行。

## 这份文档为什么存在

它是 260729 从三个地方合并出来的：`CLAUDE.md`（本地维护，不进仓库）、`CONTRIBUTING.md`（公开
摘要）、`架构总览.md`（四个章节）。也就是说同一批约定当时有**三份**，其中两份是副本。

副本已经开始分叉：CONTRIBUTING 的自测清单停在 2 条（实际 6 条）、安全不变量停在 3 条（实际
8 条）、还有两处写着「dev server 实时读模板」——这句话是错的，而且**正是因为相信了它，260729
有人对着缓存的旧页面查了半天改动为何不生效**。

教训不是「副本要记得同步」，而是：

> **给腐化开的药方如果需要人工定期同步，它自己就是下一处腐化。**

所以这份文档是唯一真源，其他地方一律链接过来。**要加新约定，加在这里**；在别处又写一份，
三个月后它就是下一个把人带沟里的东西。
