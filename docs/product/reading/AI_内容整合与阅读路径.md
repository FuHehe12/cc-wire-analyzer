# 内容整合与阅读路径

本书把使用说明、报文解释和设计原理放入对应工作流。它没有把所有原文件变成附件；技术契约、软件内置帮助和历史研究仍保留各自用途。

## 选择阅读深度

| 想解决的问题 | 阅读入口 |
|---|---|
| 初次认识软件并开始使用 | [典型问题与入门](#reader-first-visit)，再看第 1 节使用方法 |
| 查不到记录，或搜索结果为空 | [搜索区域与 coverage](#reader-search-coverage) |
| 不理解请求、响应与解释的区别 | 第 4 节操作详解与报文解读；[阅读辅助的边界](#principle-reading) |
| 想知道图中的关系从哪里来 | 第 5 节图例与轨迹方法；[身份、类型与关系](#principle-attribution) |
| 想比较成本、错误与分析结论 | [统计口径](#reader-usage-fields)、[诊断原理](#principle-diagnose)，再看第 6 节研究方法 |
| 想理解压实、归档与删除 | [存储原理](#principle-storage) |
| 想通过接口操作 | [实例与接口边界](#reader-api-boundaries)，具体 Agent 帮助仍由软件提供 |
| 担心数据去了哪里 | [保存与网络操作](#reader-data-destinations) |
| 想给其他工具做同类分析器 | [观测面](#principle-surfaces)与[迁移边界](#principle-evolution) |

## 原材料的去向

| 原材料 | 本书吸收的内容 | 仍保留的用途 |
|---|---|---|
| 界面导览、报文解读 | 操作细节、异常处理、类型解释、示例和识别边界，分别进入各工作流 | 开发端字段、完整映射等未逐项替代的内容继续保留；旧解释发现冲突时不照搬 |
| 同类工具构建手册 | 观测面、接管、记录、身份、查询、诊断、存储和迁移原理 | 其他工具研究案例与具体实验背景 |
| 轨迹研究方法、算法和教训 | 有效判据、算法限制、图的读法与维护要点 | 重复稿已删除；独有复算条件归入 issue，原始录制保留 |
| 路线与待办 | 有效研究问题、体检与清理交互候选归入对应章节，明确尚待设计 | 旧版本排期与过期状态表删除，历史依据归入 issue |
| 架构总览、开发约定 | 产品原理进入正文；[开发约定](../../development/开发约定.md) 全文收入开发参考 | 架构与开发约定正文在 `docs/development/` 维护，说明书由当前正文生成 |
| API 契约 | 使用路径进入正文；[完整 API 契约](../../usage/API契约.md) 收入开发参考，保留全部字段与错误规格 | 正文在 `docs/usage/API契约.md` 维护，检查工具直接读取 Markdown 规范 |
| 软件内置 AI_USAGE | 本书只说明其入口和作用 | 正文在 `docs/usage/AI_USAGE.md`；运行读取与打包路径同步到此处，帮助保持离线自足 |
| 官网、三语 README | 产品问题、入门步骤、隐私与数据去向 | 披露材料冻结在 `public/`，当前不回写、不发布、不建立同步 |
| 文档策略 | 维护清单与规则并入 [开发约定](../../development/开发约定.md) | 只维护开发约定第十一节，不保留单独跳转文档 |
| 曝光研究 | 官网职责进入正文 | 跨项目教程保留在 `local/notes/`，不随说明书生成 |

当前产品源在 `docs/product/`，开发规则在 `docs/development/`，软件用法与契约在 `docs/usage/`，迁移方法在 `docs/guides/`。`tools/build/build_manual.py` 从本地源生成 `dist/manual/index.html`，HTML 不作为编辑真源。内置帮助的运行读取与打包路径已随目录迁移调整。历史取舍与复算条件留在 issue，原始录制未移动；`public/` 仅保留冻结披露断面。

## 冲突怎样处理

旧材料中的“完整原始字节”“今天不能压实”“全文侧车”和“最优浪费”不能不加条件地进入当前功能说明。正文分别区分已保存记录与原始字节、整日与滚动压实、摘录与原文、启发式路径与可证明结论。研究数字不作为当前版本的性能承诺。
