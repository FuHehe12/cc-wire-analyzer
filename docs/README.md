# 文档索引

这个目录按**文档会不会腐化、以及腐化了要靠什么发现**分层。两类的维护策略互不相同——
把它们平铺在一起会导致一件坏事：要么用最严的规矩管住不需要管的，要么用最松的漏掉必须盯的。

| 目录 | 装什么 | 谁在什么时候打开 | 腐化风险 | 靠什么守 |
|---|---|---|---|---|
| [`reference/`](reference/) | 精确描述**当前实现** | 用这软件的人 / 改它的人 / 调它接口的 agent | **高**——代码一改就过时 | `tools/doc_audit.py` 机器对账 |
| 本目录根下 | 元文档：讲文档体系自己 | 改文档的人 | 低 | 体系变了才改 |

**受众在本项目之外的那一份不在这里**：[`handbook/同类工具构建手册.md`](../handbook/同类工具构建手册.md)
讲的是「做这类工具会遇到什么」，读者是要给别的 agent 工具造分析器的人，它**不该随本项目的
每次迭代更新**——260904 从 `docs/methodology/` 搬到仓库根的 `handbook/`，docs/ 于是只剩
「本项目的说明书 + 讲文档体系的元文档」两类。

## reference/ — 参考手册（进对账）

| 文档 | 谁 | 什么时候看 |
|---|---|---|
| [界面导览.md](reference/界面导览.md) | 用这软件的人 | 4 个 tab 加详情视图各看到什么、数据从哪来、哪些能力入口很深 |
| [报文解读.md](reference/报文解读.md) | 用这软件的人 | 想读懂 CC 的报文本身——每种 `kind` 的报文逐一解读 + 识别方法论（界面上的 kind chip 看不懂先看这篇）|
| [架构总览.md](reference/架构总览.md) | 改这软件的人 | 想搞懂这软件怎么搭起来的——模块怎么分层、数据怎么流过它们 |
| [开发约定.md](reference/开发约定.md) | 改这软件的人 | **改代码前必读**：安全不变量、惯犯 bug、识别体系七层地图、防御性设计、自测与静态对账清单 |
| [API契约.md](reference/API契约.md) | 调接口的人 / agent | 接口规格——端点 / 字段 / 枚举的真源 |
| [AI_USAGE.md](reference/AI_USAGE.md) | 驱动它的 agent | 用 agent 驱动本工具（这份随产物打包，`--help` 与 `GET /api/ai-guide` 交出的就是它） |

> **`报文解读.md` 260904 从 `methodology/` 搬进来**：它此前被归成"低腐化、不进对账"，
> 而实测它**随代码腐化、也一直在对账里**——kind 枚举的对账扫的就是它。搬家那天在
> `界面导览.md` 里逮到一处腐化实证：交叉引用写着"CC 的 9 种请求"，而实际早已是 11 种。
> 归错类的代价不是名义上的——它让这份文档在"不用管"的名单上待了几个月。

**为什么这一类要机器对账**：它们承诺「代码现在就是这样」。这个承诺没有任何东西自动维持——
代码改了文档不会跟着动，而读者又完全信任它。`doc_audit` 因此对账端点、CLI 子命令、
`IDX_SCHEMA`、外观 token 与文档内的路径链接。

> **范围是路径规则，不是文件清单**：`doc_audit` 扫 `docs/**` 与 `handbook/**`（后者也引用
> 本项目的端点与文件路径，断链照样要查），而"描述当前实现"这一类只认 `reference/`。
> 新增一份参考手册放进这个目录就自动进对账——不必记得去某张名单上登记，而名单恰恰是最容易
> 忘记维护的东西。

## 不在这里的一类

| 内容 | 在哪 | 为什么不在 docs/ |
|---|---|---|
| **项目叙事**（这软件怎么走到今天、当前状态、下一步） | [CHANGELOG](../CHANGELOG.md) 顶部速览 + 发版 tag | 它随进度变，属于流水而非手册 |
| **给别的 agent 工具造同类分析器**（逐个能力单元 + 「换 harness 时哪些变、哪些不变」） | [`handbook/`](../handbook/同类工具构建手册.md) | 受众在本项目之外，讲的是可迁移方法而不是本项目现状。留在 docs/ 有两个坏处：它会被当成本项目手册的一部分维护，而想找「怎么改这个软件」的人还得先跳过它 |

**「项目叙事」曾经长在 `架构总览.md` 末尾**（演进主线 / 设计哲学 / 代码气质三节），260808 迁出。
迁出的理由不是它们写得不好，而是它们在别处已经有更合适的归宿，留在手册里只会分叉出第二份
副本——而副本从来只朝一个方向发展：过时。迁出时那三节里确实有一条已经说错了话
（写着「剩下的是跨天趋势」，而跨天趋势早就做完了）。
